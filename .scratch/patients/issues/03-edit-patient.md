# 03 — تعديل بيانات المريض

Status: ready-for-human
Execution: complete

**What to build:** يستطيع الموظف المخول تعديل الملف النشط مع الحفاظ على هوية المريض وقواعد مشاركة الهاتف.

**Blocked by:** 01 — تسجيل المريض وفتح ملفه الأساسي.

## Acceptance criteria

- [x] تعديل الحقول المعتمدة يتطلب patients.write؛ البيانات تظهر بعد تأكيد الخادم.
- [x] يبقى رقم الملف ثابتًا ولا يقبل التعديل من العميل.
- [x] تُطبق قاعدة الهاتف بعد توحيد الصيغة عند كل تعديل، ويُستثنى السجل نفسه من فحص التعارض.
- [x] تحويل الطفل إلى بالغ يُرفض عند وجود بالغ آخر بالرقم، ويمكن إتمامه برقم غير متعارض دون فقد السجل.
- [x] يُرفض التغيير المتعارض كاملًا برسالة مفهومة؛ تبقى البيانات السابقة، وتُختبر حالات التزامن.
- [x] لا تضيف هذه المهمة علاقات أسرية أو محتوى طبيًا أو واجهة أرشفة؛ تضيف مهمة 04 حظر تعديل المؤرشف.
- [x] المسار كامل عبر الواجهة وAPI والتخزين، مع اختبارات سلوك HTTP والصلاحيات وعزل العيادات ومنع وصول مدير البرنامج.
- [x] تعمل العربية والفرنسية واتجاهاتهما، مع حالات التحميل والفراغ والخطأ ومنع الإرسال المكرر؛ يُوثق التحقق البصري أو سبب تعذره.
- [x] يُحدد عقد العملية ويُوثق قبل التنفيذ وفق مواصفة المرحلة وقواعد تصميم المشروع؛ لا تُضاف وظائف مستقبلية.
