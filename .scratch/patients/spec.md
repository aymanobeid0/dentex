## Problem Statement

تحتاج العيادة إلى تعريف مرضاها والوصول إلى بياناتهم دون خلط هوية المريض برقم الهاتف، خصوصًا عند استخدام الأطفال رقم ولي الأمر. لا توجد حاليًا وحدة مرضى منفذة؛ الموجود صلاحيات مهيأة للوحدات المستقبلية.

## Solution

سجل مرضى مستقل لكل عيادة، يتيح التسجيل والبحث وفتح الملف الأساسي والتعديل والأرشفة والاستعادة. لكل مريض ملف مستمر ورقم تلقائي ثابت. تتوسع صفحة الملف لاحقًا بالمواعيد والزيارات والخطط والدفعات والوصفات عند اعتماد وظائفها وتنفيذها.

## User Stories

1. كموظف مخوّل، أريد تسجيل الاسم الكامل والهاتف والجنس حتى أعرّف المريض.
2. كموظف مخوّل، أريد ترك تاريخ الميلاد والعنوان فارغين عندما لا أعرفهما.
3. كموظف مخوّل، أريد تحديد «طفل» واستخدام رقم ولي أمره دون إلزام اسم الولي أو صلته.
4. كموظف مخوّل، أريد إضافة ملاحظة إدارية اختيارية.
5. كموظف، أريد رقم ملف تلقائيًا مستقلًا لكل مريض، حتى لأطفال الأسرة نفسها.
6. كموظف، أريد تسجيل بالغ وعدة أطفال بالرقم نفسه مهما كان ترتيب التسجيل.
7. كموظف، أريد منع بالغ ثانٍ من استخدام رقم بالغ مسجل في العيادة نفسها.
8. كموظف مخوّل، أريد فتح الملف الأساسي بعد التسجيل.
9. كموظف مخوّل، أريد البحث بالاسم أو الهاتف أو رقم الملف.
10. كموظف، أريد رؤية المشاركين في رقم الهاتف مع تمييز الأطفال، وفق فلتر الأرشفة.
11. كموظف مخوّل، أريد تعديل البيانات دون تغيير رقم الملف أو فقد السجل.
12. كموظف، أريد رسالة واضحة عند تعارض الهاتف أثناء الإنشاء أو التعديل.
13. كموظف، أريد تغيير تصنيف الطفل إلى بالغ، مع طلب رقم آخر إذا كان الرقم مستخدمًا لبالغ آخر.
14. كموظف مخوّل بالتعديل، أريد أرشفة الملف واستعادته دون حذف بياناته.
15. كموظف مخوّل بالقراءة، أريد إظهار المؤرشف بفلتر وقراءة ملفه.
16. كموظف، أريد منع تعديل الملف المؤرشف حتى استعادته.
17. كطبيب، أريد قراءة البيانات الأساسية وفق صلاحياتي الحالية.
18. كمدير عيادة، أريد استمرار التحكم بصلاحيات الأدوار دون إضافة صلاحية أرشفة مستقلة.
19. كموظف، أريد الواجهة والأخطاء بالعربية والفرنسية، مع اتجاه مناسب لكل لغة.
20. كعيادة، أريد منع وصول عيادة أخرى أو حساب مدير البرنامج إلى بيانات مرضاي.

## Implementation Decisions

### النطاق والبيانات

- الاسم الكامل والهاتف والجنس إلزامية. تاريخ الميلاد والعنوان والملاحظة الإدارية اختيارية.
- «طفل» اختيار صريح؛ لا يُستنتج تلقائيًا من تاريخ الميلاد ولا يتغير بمرور الزمن تلقائيًا. لا تتطلب المرحلة نموذج أولياء أمور أو ربطًا عائليًا.
- رقم الملف يولده الخادم، فريد داخل العيادة وثابت وغير قابل للتعديل أو إعادة الاستخدام بعد الأرشفة. لا يلزم تسلسل بلا فجوات.
- الملاحظة إدارية؛ لا تضم هذه المرحلة حقولًا للتشخيص أو التاريخ الطبي أو الحساسية.
- الاسم ليس مفتاحًا فريدًا، والهاتف وسيلة تواصل وليس هوية المريض.

### الهاتف والتزامن

- موريتانيا فقط: رمز الدولة +222 ورقم وطني من ثمانية أرقام، وفق خطة الترقيم الرسمية المشار إليها أدناه.
- تفصيل تقني للتنفيذ: قبول الرقم المحلي أو صورته مع +222 أو 00222، وتوحيد الأرقام العربية والغربية والمسافات والشرطات إلى قيمة معيارية واحدة قبل المقارنة. لا تعني هذه المعالجة دعم دول أخرى.
- لا تُثبت قائمة بادئات شركات قديمة دون تحقق حديث؛ التحقق الشكلي لا يثبت ملكية الرقم أو إمكانية الاتصال به. لا تحقق عبر SMS في النطاق.
- لكل رقم معياري داخل العيادة بالغ واحد كحد أقصى، وعدة أطفال، بما في ذلك الملفات المؤرشفة. ترتيب التسجيل لا يؤثر.
- تُطبق القاعدة عند الإنشاء والتعديل وتغيير تصنيف الطفل. عند التعارض يُرفض التغيير كاملًا دون تغيير جزئي للملف.
- يفرض التخزين قاعدة تفرد البالغ ورقم الملف أيضًا تحت الطلبات المتزامنة؛ فحص الواجهة وحده لا يكفي.

### القراءة والصلاحيات

- تستمد العيادة من الجلسة. البحث والقراءة والكتابة مقيدة بها؛ لا تُقبل عيادة يختارها العميل لتجاوز النطاق.
- القراءة والقائمة والبحث تتطلب patients.read؛ الإنشاء والتعديل والأرشفة والاستعادة تتطلب patients.write. لا تمنح الكتابة صلاحية قراءة مستقلة ضمنيًا؛ تدعم الواجهة الصلاحيات الفعلية للموظف.
- بقرار المستخدم في 2026-11-04: الاستقبال والطبيب يقرآن ويكتبان بيانات المرضى افتراضيًا، ومدير العيادة يملك الصلاحيات. تعديل افتراضي الطبيب موثق في `.scratch/accounts/issues/08-dentist-patient-write.md`؛ يظل المدير قادرًا على تخصيص صلاحيات الدور. لا صلاحية مستقلة للأرشفة.
- الملف الأساسي يستخدم صلاحيات بيانات المرضى؛ لا يتطلب صلاحية السجل الطبي ولا يكشف محتوى طبيًا. مدير البرنامج لا يصل لهذه الوحدة.
- تطبق تغييرات الصلاحيات على الطلب التالي وفق نظام الحسابات الحالي.

### القائمة ودورة الملف

- البحث بالاسم أو الهاتف أو رقم الملف، والنتيجة تفتح الملف. يعرض الهاتف المشترك جميع المطابقين المسموحين ضمن فلتر الأرشفة.
- القائمة الافتراضية تعرض غير المؤرشف؛ يتاح إظهار المؤرشف بفلتر مع تمييز الحالة والطفل.
- الأرشفة تحفظ البيانات وتحجز رقم الملف والهاتف وفق قاعدة التكرار. المؤرشف قابل للقراءة، ويُرفض تعديل بياناته حتى استعادته.
- لا تعرض أقسامًا مستقبلية أو أرقامًا مالية أو زيارات وهمية. يظهر مدخل المرضى عند تنفيذ وظيفته فقط.

### حدود التنفيذ

- تُضاف وحدة المرضى إلى التطبيق الموحد الحالي وقاعدة PostgreSQL وPrisma؛ لا حاجة لخدمة مستقلة.
- تُحدد عقود HTTP لكل مهمة قبل تنفيذها: المدخلات والردود والأخطاء والصلاحيات، وتُوثق في عقد الواجهة دون اختراع نطاق إضافي.
- أنماط الأخطاء تتسق مع التطبيق: مدخلات غير صالحة، جلسة منتهية، منع صلاحية، سجل غير موجود أو خارج العيادة، تعارض هاتف أو تعديل مؤرشف. لا يكشف الخطأ بيانات مرضى غير مصرح بها.
- تُستخدم قواعد التصميم المعتمدة: حدود محايدة، Lucide، autofill، إطار التطبيق المشترك، العربية RTL والفرنسية LTR، وعزل اتجاه الهاتف ورقم الملف.

## Testing Decisions

- وافق المستخدم على اختبار المسار الكامل من الواجهة إلى API والتخزين، والصلاحيات وعزل العيادات واللغتين.
- تُفضل اختبارات HTTP التكاملية باستخدام Supertest وVitest وقاعدة الاختبار، على نمط اختبارات الموظفين ودورة الحساب والأدوار الموجودة؛ لا تُختبر تفاصيل داخلية بلا سلوك مرئي.
- تغطي اختبارات الواجهة باستخدام Testing Library الحقول والأخطاء والتحكم بالصلاحيات واللغتين، على نمط اختبارات الدخول والأدوار والتنقل القائمة.
- سيناريوهات حاسمة: بالغ ثانٍ مرفوض؛ أطفال متعددون مسموحون قبل الوالد وبعده؛ رقم واحد بصيغ مكافئة؛ استقلال عيادتين؛ تعارض تحويل طفل؛ ثبات رقم الملف؛ المؤرشف يحجز الهاتف؛ منع تعديله؛ الاستعادة؛ منع القراءة والكتابة عبر جلسة غير مخولة.
- اختبار طلبين متزامنين لبالغين بالرقم نفسه يجب أن يسمح بواحد فقط، مع التحقق من عدم تكرار رقم الملف تحت الإنشاء المتزامن.
- تحقق بصري وتفاعلي فعلي للشاشات بالعربية والفرنسية وعلى الهاتف والمكتب، بما يشمل التركيز ولوحة المفاتيح وحالات التحميل والفراغ والفشل. يُسجل أي تعذر بصري بوضوح ولا يُدعى اكتماله.
- نُفذت اختبارات التسجيل والملف الأساسي والتحقق البصري والتفاعلي للتذكرة 01؛ الأدلة في [handoff.md](handoff.md). تحقق التذاكر 02–04 ينتظر تنفيذها.

## Out of Scope

- المواعيد والزيارات وخطط العلاج والمخطط السني والتاريخ الطبي والحساسية والمرفقات.
- الفواتير والدفعات والأرصدة والوصفات الطبية والطباعة والتصدير والاستيراد والدمج.
- الحذف النهائي، إدارة أفراد الأسرة أو أولياء الأمور ككيانات، ودعم دول هاتف إضافية.
- لا تُعتبر تفاصيل المراحل اللاحقة أو ترتيب اعتمادياتها معتمدة بهذه المواصفة.
