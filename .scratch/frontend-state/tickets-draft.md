# سجل مسودة التقسيم المعتمد — أرشيف

حالة لاحقة: اكتملت01 و02، ولم يبدأ03–09. هذه المسودة سجل التقسيم المعتمد؛ [الفهرس](../frontend-state-migration/map.md) هو مرجع التنفيذ والحواجز.

الحالة: اعتُمد الحجم والحواف دون دمج أو فصل، ونُشرت التذاكر في2026-11-04. سجل المسودة محفوظ؛ المرجع التشغيلي فهرس التذاكر المنشورة.
التاريخ: 2026-11-04.

هذه نسخة تاريخية لحوار التقسيم؛ حالة التنفيذ والحجب الحالية في [الفهرس المنشور](../frontend-state-migration/map.md)، وليست في صياغات الانتظار أو النشر المستقبلية أدناه.
المصدر المعتمد: [المواصفة](spec.md). بند المتابعة الأب القائم يظل كما هو ولا يُغلق أو يُعدل.

## مبادئ التقسيم

كل تذكرة تقدم سلوكًا يعمل من الواجهة إلى API وقاعدة البيانات حيث يقتضي السلوك؛ لا تذكرة خادم معلقة بلا واجهة ولا تذكرة لتثبيت مكتبة فقط. أساس البيانات المشترك يُدخل في تدفق الجلسة الحقيقي بالتذكرة01 مع تهيئة ما يلزم من فصل محدود للسلوك القائم، دون تغيير معماري للخادم أو إعادة تنظيم شاملة.

يمكن أن تتعايش الشاشات القديمة مع التدفقات المرحلة مؤقتًا دون cache موازٍ داخل الميزة المرحلة. تبقى كل تذكرة قابلة للبناء والفحص منفردة، وتُزال آليات الجلب المحلية لكل تدفق عند ترحيله؛ التذكرة09 تكمل الانكماش والمراجعة العابرة للشاشات فقط.

الأرقام ترتيب تنفيذ مفضل، وليست سلسلة حجب مصطنعة. يعمل المنفذ تتابعيًا لفحص المستخدم بعد كل تذكرة كما اعتمد؛ الحواف تمثل حاجة فنية فعلية فقط.

## 01 — جلسة المستخدم واللغة عبر أساس البيانات الموحد

**Blocked by:** None.

**What it delivers:** الدخول بالهوية الصحيحة، عرض بيانات الجلسة، استمرار اللغة والاتجاه، والخروج/انتهاء الجلسة دون ظهور بيانات حساب سابق. يدخل TanStack Query والطلبات المشتركة من تدفق مستخدم فعلي وتبقى الشاشات غير المرحلة عاملة.

- الهوية وبياناتها القادمة من API تدار عبر Query، واللغة/الاتجاه في سياق محدود مع استمرار حفظ اللغة؛ لا Context يجمع بيانات الميزات أو Zustand استباقي.
- الطلبات المشتركة تصنف أخطاء الشبكة/HTTP/الدخول/انتهاء الجلسة وتستقبل إشارة إلغاء القراءات، وتفصل النتيجة غير المؤكدة للكتابة عن الفشل المؤكد؛ لا إعادة إرسال تلقائية للكتابات.
- لا تعطيل صامت لانتهاء الجلسة في الشاشات القديمة؛ تُدمج دورة الجلسة المشتركة مع حالة الهوية الحالية ومسح الشاشات التابعة لها.
- cache في الذاكرة مع هوية جلسة وعزل عيادة، وإلغاء القراءات وإهمال الردود عند تبدل الجلسة؛ لا بيانات حساسة مخزنة بشكل دائم أو مفاتيح تتضمن كلمات المرور.
- الدخول والخروج وقواعد cookie الحالية محفوظة، مع اختبار دخول حسابين متتابعين ورد متأخر وانتهاء الجلسة وفشل الدخول؛ العربية والفرنسية والاتجاه وRadix سليمة.
- تهيئة سياسة القراءة/retry ومراقبة الظهور والاتصال تُستخدم في جلب الهوية المعروضة فعليًا، دون تشغيل جلب خلفي لكل موارد التطبيق.

## 02 — قائمة المرضى والبحث وقراءة الملف ببيانات متجددة

**Blocked by:** 01 — أساس البيانات والجلسة.

**What it delivers:** البحث في الجدول وفتح ملف المريض وقراءة البيانات المحدثة، مع الرجوع إلى قائمة ببحث فارغ وصفحة أولى وبقاء القراءة المحملة أثناء انقطاع الاتصال مع تنبيه.

- ترحيل قراءة القائمة/الملف إلى Query بمفاتيح المورد ومعاملاته ضمن الجلسة والعيادة؛ إزالة الجلب الموازي لهذين التدفقين.
- الحفاظ على300ms وEnter/البحث والمسح الفوريين وIME والتركيز والصفحات وإلغاء القديم وتجاهل الرد وJSON المتأخرين.
- تحديث كل نحو15 ثانية للمعروض فقط عند الظهور والاتصال، والتوقف بالخلفية وعند المغادرة، وإعادة التحقق عند العودة؛ polling لا يتجاوز انتظار نص البحث أو يضاعف الاستعلام.
- بقاء نسخة العرض أثناء التحديث وعند انقطاع الاتصال مع بيان الحالة، وتمييز القائمة الفارغة والأخطاء ورفض الصلاحية دون كشف بيانات غير مخولة.
- اختبارات سلوك البحث والمؤقتات والاتصال/الظهور والرجوع والعزل، وتحقق متصفح UI-to-API باللغتين دون إضافة تحرير ملف مريض.

## 03 — تسجيل مريض وحماية مسودة التسجيل ووضوح نتيجة الحفظ

**Blocked by:** 02 — قراءات المرضى ومفاتيحها وتحديثها.

**What it delivers:** إنشاء ملف مريض بحفظ مؤكد، وتحديث القائمة وفتح الملف، مع حماية المدخلات غير المحفوظة ووضوح ما إذا كان الحفظ مؤكدًا أم تعذر التأكد منه.

- ترحيل الإنشاء إلى mutation وتحديث الموارد المتأثرة بعد تأكيد الخادم فقط؛ الحفاظ على عقد التسجيل ورقم الملف والعزل وقواعد التكرار الموجودة.
- لا نجاح تفاؤلي أو تكرار تلقائي أو كتابة مؤجلة offline؛ إذا انقطع الرد تُراجع بيانات الخادم قبل المحاولة ولا يُدعى منع التكرار المضمون.
- المدخلات مسودة محلية لا يعيد الجلب تهيئتها؛ تنبيه البقاء/التجاهل عند التنقل الداخلي وتحذير المتصفح عند الإغلاق/التحميل ضمن حدوده، مع زوال dirty بعد النجاح/التجاهل.
- لا تخزين دائم للمسودة، مع استمرار Radix Select/Checkbox وتسميات الحقول والتركيز واللغتين.
- اختبارات الإنشاء ونجاحه وفشله ورد مفقود وعودة الاتصال والتحذير والتنقل، وتحقق حفظ عبر API وقاعدة اختبار معزولة.

## 04 — تعديل الموظف وأدواره مع منع استبدال تعديل متزامن

**Blocked by:** 01 — الهوية والطلبات وQuery ودورة الجلسة.

**What it delivers:** عرض الموظفين وفتح تعديل موظف وحفظ بياناته وأدواره، مع احتفاظ المدير بمسودته إذا تغير السجل ورفض الحفظ المتعارض ذريًا بدل استبدال تعديل مدير آخر.

- ترحيل قراءات الموظفين وكاتالوج الأدوار اللازمة للنموذج وكتابة تعديل بيانات الموظف وإسناد أدواره؛ باقي إجراءات دورة الموظف تستمر حتى التذكرة06 دون كسر الشاشات.
- توثيق عقد الإصدار وحدود تغييره وخطأ التعارض وخطة ترحيل البيانات القائمة قبل التنفيذ ضمن طبقات الخادم الحالية، ثم تنفيذ الإصدار والفحص الذري وربطهما بالنموذج في التذكرة نفسها.
- رفض إصدار قديم/مفقود/غير صالح حسب العقد دون كتابة جزئية أو فتح تجاوز، مع إبقاء العزل وإعادة فحص الصلاحيات وقواعد المدير النشط.
- التحديث الدوري للبيانات المعروضة لا يمسح المسودة؛ ينبه بتغيير الأصل. مراجعة أحدث نسخة تتطلب إجراء صريحًا قبل إعادة الحفظ، دون دمج أو استبدال أو ترقية إصدار صامتة.
- تنبيه تجاهل المسودة وضوابط الكتابة غير المؤكدة والقراءة offline والعربية/الفرنسية وRadix وفق النمط المشترك؛ يعاد استخدام مساعدات موجودة عند توفرها، وتُبنى حاجة التذكرة الحالية دون انتظار تذكرة غير حاجبة.
- تحقق HTTP بكتابتين فعليتين من الإصدار نفسه، ثم UI لسلوك التعارض والمراجعة؛ ترحيل جديد على قاعدة اختبار معزولة مع حفظ بيانات التطوير وقواعد الجلسات.

## 05 — تعديل منح الدور مع حماية التعارض

**Blocked by:** 01 — الهوية والطلبات وQuery ودورة الجلسة.

**What it delivers:** قراءة الأدوار والمنح وتعديل مجموعة صلاحيات دور من الشاشة الحالية، مع بقاء اختيار الدور والمسودة ورفض حفظ نسخة قديمة دون إلغاء قرارات مدير آخر.

- ترحيل قراءة الأدوار والمنح وكتابتها وتحديثها بعد الحفظ إلى Query؛ الحفاظ على صلاحيات الدور الافتراضية وقابلية تخصيصها وحماية دور المدير.
- توثيق إصدار تحرير الدور ومنحه والفحص الذري وعقد التعارض والترحيل اللازم، وتنفيذه من القراءة إلى الحفظ والشاشة واختبار التزامن دون خفض المعمارية أو استعمال credentialVersion.
- لا تحديث صامت لمسودة المنح أو إعادة إرسال بعد التعارض؛ تنبيه الأصل الأحدث والمراجعة الصريحة وتنبيه المغادرة مع استمرار ToggleGroup وCheckbox والاتجاهين.
- التحديث للمعروض فقط وضوابط retry/offline ونتيجة الكتابة غير المؤكدة وعزل الجلسة والقواعد الحالية محفوظة.
- فحص HTTP متزامن وUI للتعارض وتحديث المنح وتأثيرها على الطلب التالي في العيادة الصحيحة، مع حفظ المعاملات وقواعد المدير.

لا تعتمد05 على04: كلاهما يحتاج أساس01، ولكل منهما إصدار سجل مملوك لميزته. يُعاد استخدام التصنيف العام للأخطاء والمساعدات المشتركة في01، وأي إعادة استخدام إضافية عند التنفيذ لا تبرر فرض حافة غير لازمة. الترتيب المفضل04 ثم05 يسمح بالمراجعة والتناسق دون منع تحقق05 منفردة.

## 06 — إكمال دورة الموظف: الإنشاء والحالة وإعادة تعيين كلمة المرور

**Blocked by:** 04 — قراءات الموظفين ونموذجهم ومفاتيح تحديثهم.

**What it delivers:** إضافة موظف وتفعيل/تعطيل حسابه وإعادة تعيين كلمة مروره عبر السياسة الموحدة، مع تحديث الجدول وانتهاء الجلسات وفق القواعد القائمة ووضوح نتيجة كل إجراء.

- ترحيل ما تبقى من إجراءات الموظف إلى mutations موحدة دون مخزن بيانات موازٍ؛ إعادة قراءة الموارد ذات الصلة بعد تأكيد النجاح.
- استمرار حماية المدير الأخير وحدود التفويض والعزل وإبطال الجلسات وقواعد كلمات المرور؛ الحالة/reset تحتفظ بعقودها الخاصة ولا يفرض عليها محرر سجلات عام.
- تغييرات مؤثرة على أصل تحرير الموظف لا تسمح لحفظ قديم بتجاوز حماية04؛ تُحترم حدود إصدارها المعتمدة دون توسيع غير موثق.
- لا تكرار حفظ تلقائي أو رسالة نجاح مبكرة؛ نتيجة رد مفقود واضحة دون إعادة تعيين كلمة مرور تلقائية.
- حماية مسودات الإنشاء/الحقول السرية من الفقد حسب السياسة دون تخزينها أو تسجيلها أو وضعها في query keys؛ لغتان وتفاعل وصول محفوظ.
- اختبارات UI/HTTP لدورة الموظف والعزل وآخر مدير والجلسات مع سيناريو فشل الرد وفحص محلي.

## 07 — العيادات ومديروها عبر دورة البيانات الموحدة

**Blocked by:** 01 — هوية المدير العام والطلبات وQuery ودورة الجلسة.

**What it delivers:** عرض العيادات وإنشاء عيادة وإدارة مديريها وإعادة تعيين كلمة مرور مدير من الشاشات القائمة، مع حماية مسودة الإنشاء وتحديث البيانات ووضوح نتيجة الحفظ.

- ترحيل القائمة والإنشاء وقراءات المديرين وإعادة التعيين؛ polling للمعروض فقط وإلغاء/عزل صحيح عند التنقل والخروج.
- استمرار العقود الحالية لإنشاء العيادة ورمزها وحساب مديرها وقواعد كلمة المرور والجلسة؛ لا إضافة تحرير بيانات عيادة أو مستخدم خارج العقد.
- لا حفظ تلقائي مكرر عند فقد رد الإنشاء ولا ادعاء أن قراءة القائمة تمنع التكرار قطعًا؛ التحقق والنتيجة غير المؤكدة حسب السياسة.
- حماية مسودة إنشاء العيادة ونماذج إعادة التعيين من الفقد دون حفظ دائم لكلمات المرور، مع العربية/الفرنسية وRadix والتركيز.
- اختبارات إنشاء ورفض تكرار ومصادقة ونطاق المدير العام مقابل مستخدم العيادة، وفحص UI-to-API.

## 08 — الحساب الشخصي وتغيير كلمة المرور دون بيانات جلسة متبقية

**Blocked by:** 01 — بيانات الهوية وإبطال الجلسة والطلبات المشتركة.

**What it delivers:** عرض حساب المستخدم الحالي وتغيير كلمة المرور من النموذج القائم، مع الحفاظ على التحقق من الكلمة الحالية والخروج بعد النجاح وحماية المدخلات غير المحفوظة.

- استخدام بيانات الهوية المملوكة لـQuery دون نسخة محلية موازية لبيانات الحساب؛ التفضيلات المحلية تبقى مستقلة.
- نقل تغيير كلمة المرور إلى mutation مع الحفاظ على قاعدة الكلمة الحالية وإبطال الجلسات وعودة المستخدم للدخول بعد نجاح مؤكد.
- عند رفض الكلمة الحالية أو تحقق غير صالح لا تعاد المحاولة تلقائيًا؛ عند رد مفقود توضح النتيجة غير المؤكدة ولا يُعاد إرسال تغيير كلمة المرور.
- حماية مسودة النموذج والتنبيه قبل تجاهلها، ومسح حقولها عند الخروج/الإلغاء الناجح وفق السلوك المعتمد، دون تخزين سر في cache أو القرص أو السجلات.
- استمرار فتح/طي نموذج Radix وتركيزه وتسمياته واللغتين، واختبارات UI/HTTP للحفظ والجلسة والردود المتأخرة.

## 09 — إتمام الانتقال والتحقق عبر الشاشات

**Blocked by:** 03،05،06،07،08. تشمل هذه الحواف02 و04 و01 انتقاليًا فلا تُكرر.

**What it delivers:** تطبيق متسق عبر جميع الشاشات الحالية، لا يعيد بيانات جلسة قديمة ولا يبقي جلبًا محليًا موازيًا للتدفقات المرحلة، مع تقرير تحقق كامل ومعيار واضح للميزات المقبلة.

- حصر جميع قراءات وكتابات API وأصحابها وإزالة البقايا القديمة التي لا مستهلك لها؛ لا حذف واسع قبل انتقال مستهلكيه ولا تأجيل الاختبارات الأساسية إلى هذه التذكرة.
- فحص دورة تنقل كاملة بين المرضى والموظفين والأدوار والعيادات والحساب، مع انقطاع/عودة الاتصال وظهور/إخفاء التبويب وخروج/انتهاء جلسة ورد قديم؛ polling للمعروض فقط وعزل cache محققان.
- التحقق من حماية المسودات والكتابات المتعارضة ونتائج الحفظ غير المؤكدة عبر الشاشات، وعدم تخزين بيانات المجال أو الأسرار دائمًا مع بقاء اللغة.
- دليل تغطية مقابل قصص المواصفة44، وتوثيق المساعدات وحدود الأدوات والميزات المستقبلية دون اختراع حالة عامة أو تركيب تقني غير مطلوب.
- كامل الاختبارات دون تخطٍّ والنوع والبناء والمعمارية ومراجعة main الحديثة والتحقق المتصفح باللغتين والاتجاهين والمكتب والهاتف؛ بيئة التطوير محفوظة وشغالة لفحص المستخدم قبل PR.

## معايير لازمة في كل تذكرة

- الحفاظ على المعمارية المعتمدة وحدود العيادة والصلاحيات والعقود إلا تغييرات التعارض المعتمدة، وتوثيق أي تعذر دون تخفيف الفحوص.
- اختبارات السلوك الخارجية UI/HTTP حسب نطاق التذكرة، وقاعدة dentex_test معزولة للبيانات والترحيلات؛ لا fixtures أو reset على التطوير.
- النوع والبناء والمعمارية والفحوص المناسبة ومراجعة مقابل main مجلوب حديثًا تشمل الملفات الجديدة، ثم إبقاء السيرفر والقاعدة لفحص المستخدم المحلي قبل PR؛ لا إعادة تهيئة arabesque/2000 أو حساباتها.
- لا مكتبة Zustand استباقية أو نقل SSE/WebSocket أو تحرير مريض أو حفظ offline أو إعادة تصميم ضمن هذا التقسيم.
