# عرض خريطة المسارات وعقود انتقال التوجيه

التاريخ: 2026-11-11. الحالة: الخريطة والعقود المحددة معتمدة في١٩ و٢٠، والفهم الإجمالي معتمد في٢١ بقول المستخدم «نعم، أعتمد الفهم وننهي المقابلة». لا تنفيذ. يستكمل [قرارات المقابلة](design.md) دون توسيعها إلى وظائف المواعيد.

## خريطة العناوين المعتمدة

المقاطع التالية تقنية ثابتة بين العربية والفرنسية؛ النصوص الظاهرة مترجمة. لا تتضمن اسم المستخدم أو رمز العيادة أو نص البحث أو حقول المسودات.

الصفحتان الخاصتان بالدخول خارج إطار الشريط. الرئيسية وحسابي صفحتان منفصلتان داخل إطار العيادة المستمر؛ تضاف الرئيسية إلى التنقل. لا إحصاءات أو مواعيد أو أصفار تمثيلية في الرئيسية الآن. تظل إحصاءات اليوم ومحتوى المواعيد لرئيسية لاحقة بعد جاهزية المواعيد دون إنشاء تذاكرها تلقائيًا أو تعديل التذاكر الخمس.

تحرير ملف المريض وأرشفته واستعادته، وإنشاء/تعديل الموظف وإجراءاته، وإنشاء العيادة وإدارة مديريها وتغيير كلمة المرور تبقى داخل الصفحة نفسها دون مسارات مستقلة جديدة. فلاتر البحث والمسودات داخل الذاكرة وفق القرارات القائمة.

## التحويلات والهوية

- تحول الروابط القديمة المعروفة #patients و#patients/new و#patients/:id إلى نظيرتها في الخريطة مع replace ودون محطة رجوع زائدة؛ لا ينفذ جزؤها كوجهة حرة ولا يتجاوز نوع الحساب أو الصلاحيات.
- فتح رابط محمي أول مرة دون جلسة يحتفظ بالوجهة الداخلية المناسبة لإعادتها بعد دخول حساب مخول. إذا لم يكن نوع الحساب أو صلاحياته مناسبًا، يطبق المنع أو الافتراضية وفق سبب الدخول؛ لا يفتح مقصدًا خارجيًا أو يعرض بيانات قبل التحقق.
- بعد انتهاء جلسة كانت صالحة، تمسح البيانات والمسودات ويُلغى مقصد العودة القديم؛ إعادة الدخول إلى الافتراضية دائمًا. الخروج الاختياري يمسح مقصد العودة أيضًا. إعادة التحميل التي تكشف أن الجلسة غير صالحة لا تعيد تلقائيًا مسودة سابقة أو سرًا.
- إذا تغيرت الهوية أثناء فتح التطبيق، تعاد مراجعة المسار تحت الهوية الجديدة قبل تركيب الميزة؛ الردود المتأخرة لا تعيد بيانات مالك سابق. لا تعديل لعقد الجلسة أو تخزين سر في العنوان.
- عند فتح مسار معروف غير مسموح، تعرض صفحة منع وصول مع طريق للصفحة الافتراضية دون خروج تلقائي. المسار غير المعروف يعرض عدم وجود الصفحة؛ ملف غير موجود أو خارج العيادة يلتزم عقد الملف القائم دون كشف وجوده.

## التغيير المعماري المحدد المقترح

### القاعدة الحالية والبديل

تنص معمارية الواجهة المعتمدة على ملكية طبقة تركيب التطبيق للتنقل، واستقلال الميزات والحارس العام. التنفيذ الحالي يحتفظ بحالة الصفحة في التطبيق، لكن المرضى يقرؤون العنوان ويكتبونه مباشرة، والدخول يملك نوع النموذج محليًا. البديل الأقل تغييرًا هو إبقاء التنقل اليدوي وروابط المربع؛ المستخدم اختار استبدالهما، فلا نضيف مصدرًا موازيًا لتحديد الشاشة.

### تركيب التطبيق

- تملك طبقة app تعريف المسارات والموجّه createBrowserRouter وRouterProvider والتحويلات وحراسة الهوية والصلاحيات وصفحات المنع وعدم الوجود والرئيسية الخفيفة. لا تستخدم loader/action لتملك نسخة موازية من بيانات الأعمال أو الهوية؛ تبقى Query ونطاق النقل كما هما.
- يصبح العنوان مصدر تحديد الشاشة، وتزال page كحالة تنقل مستقلة. يجوز اشتقاق مفتاح عرض للشريط من المسار. روابط الشريط داخل app وتستخدم الموجّه، دون قراءة العنوان أو تعديل سجل المتصفح من الميزات.
- تبقى دورة الجلسة داخل auth. ينسق app بين الهوية وسبب فتح الدخول: رابط أولي أو انتهاء جلسة أو خروج. لا تتوسع Session لتملك المسارات، ولا تنتقل ملكية الهوية أو QueryClient إلى الموجّه.
- يبقى التخطيط مركبًا بين صفحات الحساب نفسه لحفظ طي الشريط، ويستمر العزل عند استبدال الجلسة. تبقى شاشة العيادات وسياقها ومسودتها مركبة في شجرة مدير البرنامج عند زيارة حسابي؛ لا تنقل بيانات أعمالها إلى حالة عامة أو تخزين دائم، وتتوقف قراءاتها غير المعروضة.

### واجهة المرضى

- تعلن ميزة المرضى نوعًا محدودًا باسم PatientView يمثل قائمة أو تسجيلًا أو ملفًا بمعرف patientId؛ لا يتضمن عنوانًا نصيًا أو كائنًا من الموجّه.
- يتلقى PatientPage مدخل view ومخرج onNavigate(view). يترجم app العنوان إلى المدخل وطلبات الميزة إلى العناوين. يمرر العرض داخليًا إلى hook المرضى بدل قراءة hash، وتزال كتابة hash ومستمعاته وعمليات تعديل السجل الخاصة به.
- يعلن نوع العرض والصفحة عبر index القائم دون كشف ملفات داخلية. تبقى اللغة والصلاحيات وonExpired وتسجيل الحارس في مسؤولياتها القائمة. نجاح التسجيل يفتح الملف للقارئ أو يعرض إيصال الكتابة وفق السلوك الحالي.
- لا يتغير عقد قراءة المريض أو تسجيله أو تعديله أو أرشفته، ولا تعتمد الميزة على app أو الموجّه أو ميزة أخرى.

### واجهة الدخول

- يعلن auth نوع LoginKind (عيادة أو برنامج). يتلقى LoginPage مدخل kind ومخرج onKindChange(kind) مع مخرجات الدخول الحالية؛ يحدد العنوان نوع الدخول بدل حالة محلية موازية.
- تحتفظ auth بملكية الحقول وطلبات المصادقة ورسائلها. التبديل يمسح كلمة المرور والخطأ ويحفظ اسم المستخدم ورمز العيادة محليًا كما يفعل التدفق الحالي؛ لا أسرار في العنوان أو التخزين الدائم.
- لا تستورد auth الموجّه أو app. ينسق app بين نوع المسار والهوية، ولا يعيد استخدام مسودة دخول عبر هويات مختلفة.

### عقد حراسة المسودة العام

- يبقى useDraftGuard وNavigationGuard عامين دون استيراد الموجّه. يضاف إلى طلب المغادرة الحالي رد اختيار اختياري onStay بجانب callback المغادرة؛ تظل استدعاءات الداخل التي لا تحتاجه صالحة.
- الحالة النظيفة تنفذ المغادرة؛ البقاء أو Escape ينفذ onStay؛ التجاهل يمسح المسودة ثم ينفذ المغادرة. إذا كان إرسال جارٍ ترفض محاولة التنقل وتلغى، دون صف انتظار أو تنفيذ تلقائي لها بعد الحفظ.
- يربط app هذا العقد بـuseBlocker: الموافقة تكمل محاولة الموجّه نفسها، والبقاء أو الانشغال يلغيها مع سلامة العنوان وموضع سجل المتصفح. لا ينشئ callback محاولة تنقل ثانية أو حوار تجاهل ثانٍ أو مدير سجل موازٍ.
- يستمر استثناء حفظ مسودة العيادات عند زيارة حسابي والعودة، مع منع التنقل أثناء الإرسال وحراسة الخروج. انتهاء الجلسة يزيل بياناتها فورًا ولا ينتظر موافقة على الاحتفاظ بمسودة جلسة لم تعد صالحة.
- تراجع مواضع تسجيل الحارس ومستهلكوه: المرضى والموظفون والأدوار والحساب والعيادات ومديروها. تبقى إعادة التركيز والتحذير من إغلاق الصفحة وإعادة تحميلها ضمن حدود المتصفح، ولا يستعمل callback قديم لمحاولة جديدة.

### تجهيز الخادم والحزم

- يضاف React Router8.5.1 بوصفه الإصدار المستقر المتحقق منه لهذه الخطة، مع نسخة قفل محددة والتحقق من متطلباته وقت التنفيذ. أي توصية لنسخة أحدث لاحقًا تحتاج تحققًا جديدًا؛ لا تغيير نطاق تلقائي.
- تضبط متطلبات Node المعلنة لتضمن الحد المطلوب، وتثبت نسخة البناء والصورة. القفل الحالي لـReact يحقق الحد المقروء؛ هذا لا يثبت توافق بيئات النشر كلها.
- في تجهيز Express للإنتاج، يضاف إرسال صفحة التطبيق لطلبات القراءة والتصفح عند فتح المسارات الداخلية أو تحديثها، بعد حماية مسارات البيانات وخدمة الملفات. لا يعترض /api، ولا يقدم صفحة التطبيق بدل ملف ثابت مفقود أو لطلب كتابة. تبقى أخطاء البيانات وفق المعالج الحالي.
- لا يتغير تنظيم الخادم أو طبقاته أو معاملاته أو ملكية جداوله أو مخطط القاعدة. دعم العناوين تعديل في تركيب الطلبات فقط، وقد وافق المستخدم على مبدئه في١٧.

## الأثر والمخاطر والبدائل

- الملفات والعقود المتأثرة: تركيب التطبيق والتنقل والتخطيط والشريط، واجهة PatientPage ونوع عرضها وhook المرضى، واجهة LoginPage ونوعها وhook الدخول، عقد NavigationGuard والحارس ومواضع تسجيله، تجهيز الطلبات في server/app.ts، والحزم وقفلها ومتطلبات التشغيل واختبارات السلوك. لا استيراد لداخليات ميزة أو تخفيف لفحص الاعتماديات.
- المخاطر: فقد المسودة بسبب إعادة تركيب الصفحات، ازدواج حراسة الرجوع، اختلاف العنوان عن الشاشة، العودة إلى مقصد قديم بعد الخروج، وفشل الروابط المباشرة في الإنتاج. تثبت معالجتها باختبارات العنوان والتاريخ والهوية والمسودة ونسخة إنتاج معزولة.
- البدائل: إبقاء التوجيه اليدوي، أو موجّه يستخدم علامة المربع، أو قراءة الموجّه داخل الميزات. اختار المستخدم المسارات النظيفة وملكية التطبيق للتوجيه؛ المقترح المحدد يحفظ ملكية البيانات ويغير عقود إدخال العرض وطلب التنقل والحراسة فقط.
- أجاب المستخدم في١٩ «نعم، أعتمد خريطة العناوين المقترحة»، وفي٢٠ «نعم، أوافق على العقود والتغييرات المحددة». سُجل النطاق في المرجع المعماري قبل الكود؛ لا تطبيق قبل تأكيد الفهم المشترك وتكليف التنفيذ، ولا موافقة على استثناءات أو توسعات أخرى.
