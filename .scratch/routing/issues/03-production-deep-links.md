## Acceptance criteria

- [x] يرسل خادم التطبيق صفحة الواجهة لطلبات فتح المسارات وتحديثها للقراءة والتصفح، دون اعتماد إعداد خاص خارج المشروع. تبقى واجهات البيانات وخدمة الملفات ومعالج الأخطاء في ترتيب يحفظ العقود.
- [x] لا تحول طلبات بيانات مجهولة أو مرفوضة أو ملفات ثابتة مفقودة أو طلبات كتابة إلى صفحة واجهة ناجحة؛ تختبر الحالات بالطلبات ونوع الرد والسلوك الظاهر.
- [x] يفحص متصفح حقيقي نسخة بناء إنتاجية معزولة: رابط ملف مباشر بلا جلسة ثم الدخول، التحديث مع الجلسة، الروابط القديمة، المنع وعدم الوجود والرجوع والتقدم. هذه تذكرة وظيفة إنتاج محددة لا سلة لاختبارات مؤجلة من01 أو02.
- [x] تثبت نسخة Node المستخدمة في البناء والصورة ومتطلبات التشغيل، ولا يستنتج توافقها من الجهاز المحلي. لا تغيير لخدمات الأعمال أو قاعدة البيانات أو حسابات المستخدم أو عزل العيادات.
- [x] تستمر الفحوص والمعماريتان والتصميم واللغتان؛ يترك التطبيق وقاعدة التطوير الصحيحان للمستخدم بعد إثبات النسخة وفق الإجراء القائم، دون نشر أو طلب دمج قبل فحصه.

- [x] تُطبق فقط خريطة التوجيه والعقود المعمارية المحددة المعتمدة؛ لا تغيير لملكية الهوية وبيانات الخادم أو حدود الوحدات أو تخفيف للفحوص، وأي تغيير آخر يعرض للموافقة قبل تطبيقه.
- [x] يثبت سلوك الشريحة من الواجهة والطلبات الفعلية المناسبة، لا تفاصيل تنفيذها؛ تنجح اختبارات نطاقها واللغتين والاتجاهين والهاتف والمكتب ولوحة المفاتيح، ويسجل أي تحقق متعذر بوضوح دون ادعاء نجاح.
- [x] تنجح فحوص النوع والبناء ومعماريتي الخادم والواجهة والمراجعة المطلوبة مقابل main مجلوب حديثًا مع تثبيت الالتزام وشمول الملفات الجديدة والعمل غير الملتزم به.
- [x] تُحفظ قاعدة التطوير وحساباتها وأسرارها ومنحها وبيانات فحص المستخدم دون تهيئة أو اختبارات عليها؛ البيانات المصطنعة في بيئة معزولة فقط، ولا مخطط أو ترحيل مطلوب لهذا الانتقال.
- [x] بعد التنفيذ تُثبت نسخة التطبيق ومصدرها وقاعدتها ويترك التطبيق وقاعدة التطوير يعملان لفحص المستخدم وفق الإجراء المعتمد، مع تحديث دليل التحقق والفهرس والتسليم؛ لا طلب دمج قبل انتهاء فحصه.
