# 01: حجز موعد من ملف المريض مع منع التداخل

**What to build:** يفتح الموظف نافذة حجز من ملف مريض قائم، والمريض مختار مسبقًا، ويحدد طبيبًا ووقتًا ومدة وملاحظة. يحفظ الخادم حجزًا صحيحًا أو يرفضه بوضوح مع بقاء المسودة. هذه أول شريحة كاملة من الواجهة إلى التخزين، دون انتظار شاشة المواعيد العامة.

**Blocked by:** None (can start immediately). لا تذاكر سابقة؛ بوابة الموافقة المعمارية قبل تطبيق التوسعات كما في معايير القبول.

Status: ready-for-agent
Execution: not-started

قصص المواصفة: 1،8–24،28،40–41،55؛ و60–66 بحسب التدفق.

## Acceptance criteria

- [ ] قواعد توقيت العيادة والمدة ودقة البداية ونهاية اليوم والحاضر والمستقبل وأهلية الطبيب والمريض وفق المواصفة.
- [ ] منع تداخل الطبيب أو المريض حتى تحت طلبات متزامنة دون تجاوز للمدير؛ التتابع مسموح، واختلاف ملفات أفراد الأسرة مستقل رغم اشتراك الهاتف.
- [ ] الإنشاء بحالة محجوز وتوثيق المنشئ والوقت، مع تأسيس حماية التحرير وتاريخ التغييرات منذ إنشاء الحجز. محجوز وحضر وحدهما مانعان للوقت منذ البداية، دون إظهار إجراءات غير منفذة.
- [ ] إنشاء بصلاحية الإدارة، والوصول إلى الملف بصلاحية قراءة المرضى القائمة؛ لا يشترط عرض المواعيد لإنشاء حجز. تأكيد محدود ورسائل تعارض لا تكشف حجوزات غير مخولة.
- [ ] مسودة مستقلة وتأكيد خادم وعدم إعادة إرسال تلقائي عند فقد الرد. يمكن التحقق من التخزين في الاختبار قبل وجود قراءة شاشة02؛ لا حاجة لشاشة مؤقتة أو منفذ اختبار إنتاجي.
- [ ] اختبارات فعلية للتزامن والعزل والصلاحيات وحدود الوقت، وفحص النافذة باللغتين والهاتف والمكتب ولوحة المفاتيح.

- [ ] تُوثق عقود العمليات قبل الكود، ويُلتزم بالمعمارية وملكية الوحدات والمعاملات والواجهات المعلنة. أي توسعة معمارية محكومة بالإذن تُعرض محددة للمستخدم وتنتظر موافقته قبل تطبيقها؛ اعتماد التقسيم ليس هذا الإذن.
- [ ] تُطبق مراجع تصميم الواجهة والمكونات العامة وإدارة الحالة والمهارات الهندسية المعتمدة دون تخفيف للفحص أو استيراد داخليات ميزات أخرى.
- [ ] تنجح اختبارات سلوك هذه الشريحة من الواجهة إلى التخزين مع الاختبارات التكاملية المناسبة على قاعدة مصطنعة معزولة، وفحص فعلي للعربية والفرنسية والهاتف والمكتب ولوحة المفاتيح؛ يسجل أي تحقق متعذر بوضوح ولا يدعى نجاحه.
- [ ] تنجح فحوص النوع والبناء ومعماريتي الخادم والواجهة والمراجعة المطلوبة مقابل main مجلوب حديثًا مع تثبيت الالتزام وشمول الملفات الجديدة والعمل غير الملتزم به.
- [ ] تُحفظ قاعدة التطوير وحساباتها وبيانات المستخدم دون تهيئة أو تغيير أسرار أو منح أو اختبارات عليها. بعد التنفيذ تُثبت نسخة التطبيق ومصدرها وقاعدتها وتُترك تعمل لفحص المستخدم قبل طلب دمج، وتُحدّث أدلة التحقق والتسليم والفهرس دون أسرار.
