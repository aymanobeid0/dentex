# 02: عرض مواعيد اليوم وملف المريض والحجز العام

**What to build:** شاشة تفتح بقائمة اليوم، واختيار يوم آخر والتصفية والبحث وفتح التفاصيل. تتيح الحجز باختيار مريض موجود، وتعرض مواعيد المريض داخل ملفه مع استعمال زر الحجز من01.

**Blocked by:** 01: حجز موعد من ملف المريض مع منع التداخل

Status: ready-for-agent
Execution: not-started

قصص المواصفة: 2–3،38،42،45،48–60،66؛ و16–17،61–65.

## Acceptance criteria

- [ ] فلاتر الطبيب والحالة والبحث بالمريض بالاسم أو الهاتف أو رقم الملف ضمن الفترة المختارة. كل الحالات ظاهرة افتراضيًا مع تمييز الملغى.
- [ ] البداية والنهاية والمريض ورقم ملفه والطبيب والحالة في العرض الأساسي، والهاتف والملاحظة في التفاصيل، وتاريخ الإنشاء ضمن تاريخ التغييرات.
- [ ] اختيار مريض نشط ببيانات محدودة لصاحب الإدارة ولو لم يملك قراءة المرضى، دون كشف عنوان أو ملاحظات أو معلومات طبية أو فتح الملف ضمنيًا.
- [ ] صاحب الإدارة دون العرض يمكنه إنشاء الحجز وتلقي تأكيد فقط؛ لا قائمة أو تفاصيل أو تعديل حجز قائم. صاحب العرض يرى جميع أطباء عيادته؛ العيادة الأخرى ومدير البرنامج ممنوعان من البيانات والتاريخ.
- [ ] قسم مواعيد المريض يتطلب قراءة المرضى وعرض المواعيد معًا، وزر الحجز يبقى متاحًا لصاحب الإدارة وفق شروط الوصول إلى الملف. يقتصر القسم على المريض المعني دون زيارات أو معلومات مالية.
- [ ] حجوزات الطبيب المعطل أو المنزوع الدور والمريض المؤرشف تبقى ظاهرة مع تنبيه دون إلغاء أو نقل تلقائي أو تغيير عمليات التعطيل والأرشفة.
- [ ] تركيب الميزتين عبر التطبيق والواجهات المعلنة، مع الاستعلامات المعتمدة والتحديث الدوري للشاشة المعروضة وعزل الجلسة والإلغاء وحماية الردود القديمة.
- [ ] تحقق فعلي للقائمة والتفاصيل والحجز العام وقسم الملف باللغتين، مع الهاتف والمكتب والتركيز ولوحة المفاتيح والتحميل والفراغ والفشل وسحب الصلاحية.

- [ ] تُوثق عقود العمليات قبل الكود، ويُلتزم بالمعمارية وملكية الوحدات والمعاملات والواجهات المعلنة. أي توسعة معمارية محكومة بالإذن تُعرض محددة للمستخدم وتنتظر موافقته قبل تطبيقها؛ اعتماد التقسيم ليس هذا الإذن.
- [ ] تُطبق مراجع تصميم الواجهة والمكونات العامة وإدارة الحالة والمهارات الهندسية المعتمدة دون تخفيف للفحص أو استيراد داخليات ميزات أخرى.
- [ ] تنجح اختبارات سلوك هذه الشريحة من الواجهة إلى التخزين مع الاختبارات التكاملية المناسبة على قاعدة مصطنعة معزولة، وفحص فعلي للعربية والفرنسية والهاتف والمكتب ولوحة المفاتيح؛ يسجل أي تحقق متعذر بوضوح ولا يدعى نجاحه.
- [ ] تنجح فحوص النوع والبناء ومعماريتي الخادم والواجهة والمراجعة المطلوبة مقابل main مجلوب حديثًا مع تثبيت الالتزام وشمول الملفات الجديدة والعمل غير الملتزم به.
- [ ] تُحفظ قاعدة التطوير وحساباتها وبيانات المستخدم دون تهيئة أو تغيير أسرار أو منح أو اختبارات عليها. بعد التنفيذ تُثبت نسخة التطبيق ومصدرها وقاعدتها وتُترك تعمل لفحص المستخدم قبل طلب دمج، وتُحدّث أدلة التحقق والتسليم والفهرس دون أسرار.
