# 04: إدارة الموعد وحالاته وتاريخ تغييراته

**What to build:** يعدل الموظف الموعد المحجوز وطبيبه ومدته وملاحظته، ويسجل الحضور والغياب والإلغاء ويصحح الحالات، ويراجع تاريخ التغييرات، مع منع التعارض وفقد تعديلات الموظفين الآخرين.

**Blocked by:** 02: عرض مواعيد اليوم وملف المريض والحجز العام

Status: ready-for-human
Execution: complete

قصص المواصفة: 15،18،25–44،53،57؛ و60–66.

## Acceptance criteria

- [x] إعادة الجدولة وتغيير الطبيب للمحجوز فقط إلى الحاضر أو المستقبل مع فحص الأهلية والتداخل؛ المريض ثابت، وخطأ اختياره يعالج بالإلغاء والحجز الصحيح.
- [x] الملاحظة قابلة للتعديل في الحالات الأربع مع استمرار قيد المؤرشف، وتغييرها وحده لا يشترط إعادة تفعيل طبيب الحجز القائم.
- [x] محجوز وحضر ولم يحضر وملغى حالات يدوية دون قيد زمني للحضور والغياب أو تحول آلي أو إنشاء زيارة علاجية.
- [x] الغياب والإلغاء يحرران وقت الطبيب والمريض فورًا؛ العودة إلى محجوز أو حضر تعيد فحص التعارض ولو كان الموعد ماضيًا، دون تغيير تاريخه. لا تجاوز للمدير.
- [x] الملغى محفوظ دون حذف نهائي، وسبب الإلغاء اختياري. يمكن تصحيح أي حالة إلى أخرى مع القواعد نفسها، دون تبديل المريض أو تعديل ضمني للجدول.
- [x] الطبيب غير المؤهل لا يمنع توثيق حالة الموعد القائم؛ الإسناد أو الجدولة الجديدان يتطلبان طبيبًا مؤهلًا. المريض المؤرشف يسمح بإلغاء موعده وسببه فقط حتى الاستعادة.
- [x] الإدارة والعرض لازمان لكل كتابة على حجز قائم، وتراجع الصلاحيات والأهلية عند الحفظ. يسجل المنفذ والوقت والقيم السابقة والجديدة ويعرض التاريخ لصاحب العرض.
- [x] حماية تحرير ذرية لجميع التعديلات والملاحظة والحالة، دون حفظ جزئي أو سجل نجاح وهمي عند الرفض؛ المسودة تبقى مع مراجعة الأحدث وفقد الرد لا يعيد الكتابة تلقائيًا.
- [x] اختبارات طلبات متزامنة لإنشاء وتحرير وإعادة جدولة وتصحيح الحالات. يشمل السيناريو غيابًا مبكرًا ثم استغلال الوقت ثم رفض إعادة الحجز السابق، وتحريرًا متزامنًا ونزع صلاحية أو أهلية وأرشفة المريض.
- [x] تحقق فعلي من نافذة التفاصيل وشاشة اليوم وقسم ملف المريض باللغتين والهاتف والمكتب ولوحة المفاتيح؛ كل اختبارات هذا النطاق تنجز في التذكرة ولا تؤجل إلى التقويم.

- [x] تُوثق عقود العمليات قبل الكود، ويُلتزم بالمعمارية وملكية الوحدات والمعاملات والواجهات المعلنة. أي توسعة معمارية محكومة بالإذن تُعرض محددة للمستخدم وتنتظر موافقته قبل تطبيقها؛ اعتماد التقسيم ليس هذا الإذن.
- [x] تُطبق مراجع تصميم الواجهة والمكونات العامة وإدارة الحالة والمهارات الهندسية المعتمدة دون تخفيف للفحص أو استيراد داخليات ميزات أخرى.
- [x] تنجح اختبارات سلوك هذه الشريحة من الواجهة إلى التخزين مع الاختبارات التكاملية المناسبة على قاعدة مصطنعة معزولة، وفحص فعلي للعربية والفرنسية والهاتف والمكتب ولوحة المفاتيح؛ يسجل أي تحقق متعذر بوضوح ولا يدعى نجاحه.
- [x] تنجح فحوص النوع والبناء ومعماريتي الخادم والواجهة والمراجعة المطلوبة مقابل main مجلوب حديثًا مع تثبيت الالتزام وشمول الملفات الجديدة والعمل غير الملتزم به.
- [x] تُحفظ قاعدة التطوير وحساباتها وبيانات المستخدم دون تهيئة أو تغيير أسرار أو منح أو اختبارات عليها. بعد التنفيذ تُثبت نسخة التطبيق ومصدرها وقاعدتها وتُترك تعمل لفحص المستخدم قبل طلب دمج، وتُحدّث أدلة التحقق والتسليم والفهرس دون أسرار.
