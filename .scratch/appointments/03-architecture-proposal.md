# المواعيد03 — تركيب تسجيل المريض داخل الحجز

التاريخ:2026-11-12. الحالة: **معتمد بقول المستخدم «أعتمد مقترح03 كما هو»؛ سجل الإذن في مراجع الواجهة والعقد قبل الكود**.

## القاعدة الحالية والحاجة

تعلن patients حاليًا PatientPage وPatientView وسياق الحجز من الملف فقط. نموذج التسجيل وhook التسجيل وطلباتHTTP داخلية؛ لا يجوز للمواعيد استيرادها. نجاح التسجيل الحالي يفتح الملف لصاحب القراءة أو يعرض رقم الملف لصاحب التسجيل دون القراءة، ولا يقدم callback لاختيار المريض الجديد داخل مسودة الحجز.

## التوسعة المحددة

- تعلن patients مكوّن `PatientRegistrationPanel` ونوع `RegisteredPatientForAppointment = { id, name, fileNumber, archived: false }` عبرindex. يقبل المكوّنlang وcanWrite وonExpired وonRegistered وonCancel وonNavigationGuardChange؛ يعيد استخدام نموذج التسجيل وhook الكتابة والتحقق القائمة، ولا يعلنapi أوhook أوالنموذج الداخلي. callback لا يُستدعى إلا بعد201 وعقد التسجيل المؤكد، بهوية ورقم الملف من الخادم واسم المدخل المؤكد. لا يحتاج طلب قراءة ملف أوpatients.read.
- يضاف callback اختياري داخلي إلىhook المرضى الحالي لإرسال النتيجة المؤكدة بدل الانتقال لملف المريض عند استعمالPanel؛ يبقى سلوكPatientPage الحالي كما هو. يحتفظPanel بالتعارض وأخطاء الهاتف والطفل والترقيم والرد المفقود ومنع إعادة الكتابة. التسجيل عملية مستقلة لا تُتراجع بسبب فشل أو إلغاء الحجز.
- تعلن واجهة المواعيد فتحة `renderPatientRegistration` اختيارية فيprops الحجز والصفحة وقسم الملف. تحملonRegistered وonCancel وonNavigationGuardChange، ويملكapp تركيبPatientRegistrationPanel فيها بحسبpatients.write. لا استيراد بينpatients وappointments؛ نوع النتيجة البنيوي المحدود متوافق ولا يفرض اعتمادًا بين الميزتين.
- تظل مسودة الحجز مملوكة لنافذتها ومركبة أثناء التسجيل؛ يظهر التسجيل داخل النافذة نفسها دون نافذتين متداخلتين، ثم يختار المريض الجديد تلقائيًا بعد النجاح. يحجب تغيير بيانات الحجز أثناء التسجيل، ويجمع مالك النافذة حراسة التسجيل والحجز: التسجيل أولًا ثم مسودة الحجز عند المغادرة. البقاء يحفظ الاثنين، والتجاهل يمسح المسودات فقط، والإرسال الجاري يمنع المغادرة. تحتفظRadix بالتركيز؛ العودة من التسجيل تعيد التركيز إلى إجراء التسجيل أوالمريض المختار.
- لا تغيير لخادم المرضى أوالمواعيد أوالمعاملات أوالمخطط أوصلاحيات الحسابات. التسجيل يستخدمPOST patients القائم تحتpatients.write؛ إدارة المواعيد وحدها لا تمنح التسجيل أوقراءة الملف. لاQuery أوCRUD داخلapp، ولا تخفيف فحوص أو اعتماد جديد.

## الأثر والمخاطر والبديل

الملفات: index ومكوّنPanel وhook المرضى، props ونافذة المواعيد، تركيبapp، الترجمة والعقود والاختبارات. المخاطر: استدعاء النجاح قبل تأكيدالخادم، تكرار التسجيل بعد رد مفقود، أو ضياع إحدىالمسودتين بسبب حراسةمتنافسة؛ تختبر منفصلة وبالمتصفحباللغتين معالصلاحياتوسحبها. لا يجوز استخدامpatients.read للتحايل علىردفقده التسجيل.

البديل إبقاء التسجيل فيصفحته الحالية لا يحقق التسجيل داخلنافذةالحجز وحفظالمسودة؛ استيراد المكوّن الداخلي مباشرة يخالف المعمارية. التوسعة المحدودة تحافظ علىملكيةالمرضى وتنسيقapp.
