# 05 — التحقق البصري في Chrome

فُتحت صور Patient المرجعية في `screens/blue` و`screens/green` فعلًا. عُرض التطبيق الحقيقي على QA5159 بواجهات API مصطنعة لهوية ومريض وزيارة مغلقة تلقائيًا؛ لا كتابة API أو استخدام لحسابات وبياناتdev. ظهر الفرق بين نهاية اليوم المستحقة ووقت المعالجة، مع النص الصريح أن الإغلاق لا يؤكد الاكتمال أو المغادرة، بالعربية RTL والفرنسية LTR.

راجعت لقطات المكتب1440×1000 والتابلت834×1194 والهاتف390×844 في اللغتين. البطاقة أعلى التبويبات ومحتوى واحد ظاهر، دون overflow أفقي للصفحة؛ ارتفاع التبويب المقاس36/40/44px تقريبًا. على الهاتف يتمرر شريط التبويبات داخل حدوده، وثبت End إلى خطة العلاج وHome إلى الزيارات، مع توضيح عدم توفر القسم الطبي. فُحص الهاتف مع قائمة التنقل مغلقة؛ وُثقت أيضًا حالة بقائها مفتوحة بعد التصغير من المكتب دون نسبها إلى الحالة الافتراضية للهاتف.

تعذر التصوير أولًا، ثم نجح بعد إظهار تبويب QA المملوك للجلسة بـ`Page.bringToFront`، دون تغيير الحماية أو ترويسات المصدر. حُفظت ست صور `05-auto-closed-{ar,fr}-{desktop,tablet,phone}.jpg` في مجلد `visits-runtime` الخارجي للجلسة. عُرضت صور المكتب والهاتف مباشرة، وفُتحت صورتا التابلت المحفوظتان بأداة عرض الصور. نجحت أيضًا لقطة نافذة التصحيح العربية `04-correction-ar-desktop.jpg`؛ كشفت أن حقل السبب لم يستخدم `ui-textarea` المشتركة، فأُحيل لتصحيح التكامل. لا ادعاء فحص بصري لاحق لهذا التصحيح قبل إجرائه.

انقطع سياق أدوات المتصفح في تحديث الأدوات اللاحق، وتغير معرّف Chrome ثم أفاد التبويب أن جلسة التحكم غير متصلة. لذلك لم يُحفظ سجل JSON الأخير ولم يُثبت تنظيف الجولة الأخيرة أو قياس حقل السبب بعد تصحيحه؛ لا يُستبدل هذا القيد بادعاء نجاح. جولات04 السابقة أُزيل اعتراضها وأُعيدت للدخول قبل هذه الجولة، كما يوثق دليلها. لم تُمس تبويبات الإنتاج أو إعدادات الأمان أو المنفذ80.

هذه أدلة متصفح بمصدر بيانات مصطنع، وليست متصفحًا متصلًا بالتخزين الحقيقي؛ مسار المتصفح إلى API الحقيقي بقي محجوبًا بعائق Origin السابق. اختبارات AR/FR المتصلة بـHTTP وPostgreSQL عبر Supertest دليل مستقل. لا قارئ شاشة فعلي أو هاتف مادي أو قبول بشري.
