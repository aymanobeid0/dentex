# 03: ربط الزيارة بالموعد وحفظ استقلال السجلين

**What to build:** يربط المخول زيارة بموعد المريض في اليوم نفسه اختياريًا، دون مزامنة الحالات، وتطبق قيود إعادة الجدولة التي تحافظ على الحضور والزيارة السابقين.

**Blocked by:** 02: دخول الطبيب وسجل الزيارة وإنهاؤها.

Status: ready-for-human
Execution: in-progress

قصص المواصفة: 23–32؛45–50.

## Acceptance criteria

- [ ] يمكن وجود زيارة دون موعد أو دون رابط، ولا يؤدي تغيير الموعد إلى حضر إلى تسجيل حضور أو زيارة.
- [ ] الرابط للمريض واليوم نفسيهما، وكل موعد له زيارة واحدة كحد أقصى تحت التزامن.
- [ ] نقل الموعد قبل الدخول لا ينقل حضور اليوم إلى يوم آخر؛ الحضور الجديد يسجل عند العودة.
- [ ] بعد بدء الزيارة المرتبطة يمنع نقل الموعد إلى يوم آخر؛ المتابعة بموعد جديد دون تغيير السابقة.
- [ ] تبقى سائر قواعد المواعيد الحالية نافذة؛ لا فتح إعادة جدولة لحالة كانت تمنعها أصلًا أو تغيير المريض أو تخفيف منع التداخل.
- [ ] تحدد شروط مرجع الموعد غير المحسومة وتصحيح الرابط ضمن عقد الشريحة قبل تنفيذ الجزء المتأثر؛ أي توسعة واجهة بين المواعيد والحضور/الزيارات تعرض محددة للموافقة المعمارية قبل الكود.
- [ ] تحقق UI إلى API والتخزين للتغييرات والرفض والتزامن والعزل واستقلال الحالات باللغتين.

- [ ] قبل كود الجزء المتأثر تُوثق العقود وحدود التفاصيل المفتوحة؛ لا يُفترض اعتماد قرار منتج غير محسوم أو واجهة معمارية جديدة. تُطلب الموافقة المعمارية المحددة حيث يلزم وتُحفظ بواباتها.
- [ ] تبقى ملكية البيانات والطبقات والواجهات المعلنة والمعاملات وفق المعمارية؛ لا وصول لجداول ميزة أخرى أو استيراد داخلياتها أو تخفيف للفحص.
- [ ] تُطبق مراجع الواجهة والمكونات المشتركة وRadix وإدارة الحالة والمهارات الهندسية المعتمدة؛ العربية والفرنسية والهاتف والمكتب ولوحة المفاتيح والتركيز مثبتة في المتصفح.
- [ ] تنجح اختبارات السلوك عبر HTTP والتخزين الحقيقي المعزول واختبارات الواجهة المناسبة، مع الصلاحيات والعزل والتزامن والتعارض وفقد الرد والتراجع بحسب الشريحة؛ لا يؤجل تحقق الشريحة لتذكرة أخرى.
- [ ] تنجح فحوص الأنواع والبناء ومعماريتي الخادم والواجهة وملكية أنماط الواجهة، وتراجع التذكرة مقابل main مجلوب حديثًا مع تثبيت الالتزام وشمول الملفات الجديدة والعمل غير الملتزم به.
- [ ] تُحفظ قاعدة التطوير وحساباتها وبيانات المستخدم والvolume دون seed/reset أو تغيير أسرار أو منح تلقائي أو اختبارات عليها؛ تُثبت نسخة التطبيق ومصدرها وقاعدتها وتترك تعمل لفحص المستخدم قبل PR، وتحدث أدلة التحقق والتسليم والفهرس دون أسرار.
