## تسلسل الاختبار وحدوده

نقاط الاختبار المأذونة: HTTP العام مع PostgreSQL حقيقية معزولة، وسلوك المستخدم، وواجهة عمليات المواعيد المعلنة المرتبطة بالمعاملة لإبطال المرجع فقط.

**قيد دورة TDD الأولى:** كُتب اختبار03 الأول قبل الكود، لكن أمر sandbox أخفق قبل تنفيذ assertions. كُتب جزء التنفيذ قبل إعادة الأمر بإذن الشبكة؛ لذلك لا يُدعى red-before-code لذلك الجزء، ولا404 مقاسة. حُفظ03-red-http.json كما هو. بعده أثبت03-red-storage.json استجابة500 بدل201 قبل نشر جداول03؛ هذا دليل الحالة الملاحظة حينها، وليس تصنيعًا لدورة سابقة. لم يُرجع المصدر لإنتاج أحمر مصطنع.

الدورات المقاسة اللاحقة قبل كودها شملت: إصدار الزيارة عند تعديل الرابط؛ غياب واجهة الربط؛ غياب المرجع المسمى في التاريخ؛ استمرار ظهور التفاصيل بعد403؛ وعدم التنبيه لتغير إصدار الزيارة أثناء polling. تقارير red/green محفوظة خارجGit. التغطيات الإضافية للعقود القائمة اختبارات regression وليست كلها دورات TDD جديدة.

اختبارات HTTP تغطي يوم الدخول المختلف عن الوصول، منع الرابط لمنتظر، المريض واليوم والعزل والمدخلات والإصدارات، الربط بأي حالة، واستقلال الحالات، الفك وإعادة الربط والحجز التاريخي، فائزًا واحدًا للموعد وسباق إعادة الجدولة، وسياسة الأدوار الثلاثة الحديثة. تنتظر اختبارات كل منفذ قفل العيادة المثبت عبرpg_stat_activity ثم تسحب دوره قبل تحريره. يثبت trigger مصطنع خاص بزيارة جناح الاختبار فشل التدقيق المتأخر وتراجع إصداري الزيارة والرابط وحجز الموعد، بالمراجعة عبرHTTP. يُزال trigger والدالة فيfinally.

اختبارات UI بالعربية والفرنسية تغطي العواقب قبل الحفظ واختلاف الطبيب والإرسال مرة واحدة، وفقد الرد والمراجعة دون إعادة تلقائية، وحفظ الاختيار عند تغير مرجعه أو اختفائه أو تغير الزيارة، ومنع الاختيار المحذوف بعد الاحتفاظ بالمسودة، وحراسةEscape وإخفاء التفاصيل عند403. اختبارا AR/FR إضافيان يركبان PatientVisits ويعبران نقل الطلب إلىHTTP الفعلي للتطبيق عبرSupertest ثم PostgreSQL المعزولة، ويثبتان الرابط بقراءة التاريخ العامة بعد الحفظ. هذه سلسلة UI→HTTP→storage، **وليست متصفحًا حقيقيًا أو دليل قياسات بصريًا**.
