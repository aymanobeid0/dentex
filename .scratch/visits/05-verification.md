## Implemented behavior

- `visits.service` owns due-day decisions. Africa/Nouakchott midnight separates days; waiting uses arrivedAt and an in-progress visit uses its own startedAt. A current-day visit on a legacy older attendance remains active; invalid entries are untouched. Maintenance does not create visits or fabricate a recorded completion/departure.
- `visits.repository` discovers clinics using its own attendances only. Each clinic is processed in its own actorless transaction using the existing ClinicMutation lock scope; no TransactionManager change, cross-owner SQL, actor account or grants. Attendance and eligible in-progress visit close atomically, each version increases once, and capacity is released. Repeated processing preserves the first closure event.
- An additive migration adds optional closure timestamps to attendances/visits and adjusts terminal constraints without rewriting existing rows. Public snapshots expose `autoClosure={effectiveClosedAt,recordedAt,reason:"clinic_day_end"}`. Original arrivedAt/startedAt/recordedEndAt and correction audit remain intact. New automatic closures have recordedEndAt=null; subsequent explicit04 correction can record a current outcome while preserving closure history.
- Every visits service operation catches up in a separate prior maintenance transaction, then locks again and rechecks current actor and versions. Controller middleware catches up before UUID/body/query validation, while JSON parsing, session authentication and origin policy retain their existing ownership. A rejected human request cannot roll back an earlier maintenance commit.
- The limited exported VisitsMaintenance interface is composed into an internal startup worker. The real server starts it after listen, then every60000ms, suppresses overlaps, logs errors and retries. Shutdown clears the timer and awaits inflight work before disconnecting. Importing app starts no maintenance worker. The pre-existing express-rate-limit library creates its own900000ms cleanup timer; the import regression specifically proves absence of the new60000ms maintenance timer, without changing unrelated middleware.
- Patient history displays the automatic reason, due midnight and actual processing time in Arabic/French. Snapshot validation rejects invalid closure reason/timing. Query, correction/link drafts, patient identity card and four Radix tabs remain intact; no new CSS, store, SSE or feature dependency.
