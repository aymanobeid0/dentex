# عقد06 — 2026-11-05 قبل التنفيذ

نقاط TDD المأذونة: شاشة الموظفين وHTTP والتزامن وفق التكليف والمواصفة. لا اختبارات hooks داخلية. تبقى عقود POST الإنشاء وPATCH الحالة وPOST reset وeditVersion في [04-contract.md](04-contract.md) دون تغيير أو ترحيل. الحالة وكلمة المرور لا تكتبان أصل تحرير الاسم واسم الدخول والأدوار؛ لا توسعة للإصدار.

تنتقل الكتابات إلى mutations بلاretry أوqueue معnetworkMode always ومنع الإرسال أثناءoffline أو الإرسال الجاري. النجاح يحتاج DTO صالحًا للإنشاء والحالة، و204 لإعادة التعيين، ثم إبطال الموارد والهوية ذات الصلة. المتغيرات السرية مؤقتة في الطلب والمسودة فقط، معreset وgcTime0 للـmutation؛ لا أسرار في مفاتيحQuery أو التخزين أو السجلات.

الرد المفقود أو500 أو408 أو رد نجاح تالف نتيجة غير مؤكدة تحفظ المسودة وتحجب إعادة الإرسال حتى قراءة يدوية ناجحة ومراجعة صريحة. يعرض الإنشاء القائمة، والحالة/reset بيانات الموظف. قراءة القائمة لا تضمن منع التكرار، وقراءة الموظف لا تثبت كلمة المرور المخزنة. يبقى القرار بإعادة الكتابة يدويًا مع هذا التنبيه. رفض القراءة يبطل المراجعة حتى لو وصل رد قديم لاحقًا.

حماية المسودة والحقول السرية عبرguard وRadix وbeforeunload في حدوده؛ الإلغاء والتجاهل يمحوان الأسرار المحلية، والنجاح يحرر التحذير. لا تغيير خادم أو تفويض أو قفل أو ملكية معاملات.
