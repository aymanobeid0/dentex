## TDD والتحقق الآلي

الاختبارات عند نقطة الواجهة/HTTP المعتمدة مع ضبط الزمن والظهور والاتصال. رُصد فشل تحديث القائمة الدوري أولًا ثم نجاحه بعد Query؛ ثم فشل تحديث الملف ونجاحه؛ ثم فشل عودة بيانات مرفوضة أثناء debounce ومن cache بحث سابق، وعولجا باختباري انحدار مرئيين. لا اختبارات لتفاصيل تركيب cache أو hook داخلي.

`tests/patient-query-ui.test.tsx` يضيف10 اختبارات تكامل مرئية عبر App/HTTP، مع اختبار مستهلكين للقائمة. تغطي المعروض فقط، بقاء الصفوف أثناء التحديث والفشل المؤقت، pause/resume، منع تجاوز debounce/IME، الرجوع الفارغ، إلغاء ملف قديم وJSON متأخر، رفض الوصول وcache المتقاطع، ومشاركة الطلب/poll. اختبارات البحث والمرضى القائمة محفوظة ومكيفة بمزود الجلسة؛ اختبارات المكوّن المعزول توقف retry لتختبر نتيجة HTTP مباشرة، واختبارات App تستخدم سياسة المنتج الفعلية. إعداد scheduler في الاختبارات يبقي إشعارات Query في microtasks ضمن act مع المؤقتات المضبوطة؛ لا فحوص داخلية للمكتبة.
