# 08: الحساب الشخصي وتغيير كلمة المرور دون بيانات جلسة متبقية

**What to build:** عرض حساب المستخدم الحالي وتغيير كلمة المرور من النموذج القائم، مع الحفاظ على التحقق من الكلمة الحالية والخروج بعد النجاح وحماية المدخلات غير المحفوظة.

**Blocked by:** 01 — جلسة المستخدم واللغة عبر أساس البيانات الموحد

**Status:** ready-for-agent

**Execution:** not-started

- [ ] استخدام بيانات الهوية المملوكة لـQuery دون نسخة محلية موازية لبيانات الحساب؛ التفضيلات المحلية تبقى مستقلة.
- [ ] نقل تغيير كلمة المرور إلى mutation مع الحفاظ على قاعدة الكلمة الحالية وإبطال الجلسات وعودة المستخدم للدخول بعد نجاح مؤكد.
- [ ] عند رفض الكلمة الحالية أو تحقق غير صالح لا تعاد المحاولة تلقائيًا؛ عند رد مفقود توضح النتيجة غير المؤكدة ولا يُعاد إرسال تغيير كلمة المرور.
- [ ] حماية مسودة النموذج والتنبيه قبل تجاهلها، ومسح حقولها عند الخروج/الإلغاء الناجح وفق السلوك المعتمد، دون تخزين سر في cache أو القرص أو السجلات.
- [ ] استمرار فتح/طي نموذج Radix وتركيزه وتسمياته واللغتين، واختبارات UI/HTTP للحفظ والجلسة والردود المتأخرة.

## شروط الإغلاق لكل تذكرة

- [ ] الحفاظ على المعمارية المعتمدة وحدود العيادة والصلاحيات والعقود إلا تغييرات التعارض المعتمدة، وتوثيق أي تعذر دون تخفيف الفحوص.
- [ ] اختبارات السلوك الخارجية UI/HTTP حسب نطاق التذكرة، وقاعدة dentex_test معزولة للبيانات والترحيلات؛ لا fixtures أو reset على التطوير.
- [ ] النوع والبناء والمعمارية والفحوص المناسبة ومراجعة مقابل main مجلوب حديثًا تشمل الملفات الجديدة، ثم إبقاء السيرفر والقاعدة لفحص المستخدم المحلي قبل PR؛ لا إعادة تهيئة arabesque/2000 أو حساباتها.
- [ ] لا مكتبة Zustand استباقية أو نقل SSE/WebSocket أو تحرير مريض أو حفظ offline أو إعادة تصميم ضمن هذا التقسيم.
