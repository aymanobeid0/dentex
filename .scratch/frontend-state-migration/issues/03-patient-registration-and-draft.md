# 03: تسجيل مريض وحماية مسودة التسجيل ووضوح نتيجة الحفظ

**What to build:** إنشاء ملف مريض بحفظ مؤكد، وتحديث القائمة وفتح الملف، مع حماية المدخلات غير المحفوظة ووضوح ما إذا كان الحفظ مؤكدًا أم تعذر التأكد منه.

**Blocked by:** 02 — قائمة المرضى والبحث وقراءة الملف ببيانات متجددة

**Status:** ready-for-agent

**Execution:** not-started

- [ ] ترحيل الإنشاء إلى mutation وتحديث الموارد المتأثرة بعد تأكيد الخادم فقط؛ الحفاظ على عقد التسجيل ورقم الملف والعزل وقواعد التكرار الموجودة.
- [ ] لا نجاح تفاؤلي أو تكرار تلقائي أو كتابة مؤجلة offline؛ إذا انقطع الرد تُراجع بيانات الخادم قبل المحاولة ولا يُدعى منع التكرار المضمون.
- [ ] المدخلات مسودة محلية لا يعيد الجلب تهيئتها؛ تنبيه البقاء/التجاهل عند التنقل الداخلي وتحذير المتصفح عند الإغلاق/التحميل ضمن حدوده، مع زوال dirty بعد النجاح/التجاهل.
- [ ] لا تخزين دائم للمسودة، مع استمرار Radix Select/Checkbox وتسميات الحقول والتركيز واللغتين.
- [ ] اختبارات الإنشاء ونجاحه وفشله ورد مفقود وعودة الاتصال والتحذير والتنقل، وتحقق حفظ عبر API وقاعدة اختبار معزولة.

## شروط الإغلاق لكل تذكرة

- [ ] الحفاظ على المعمارية المعتمدة وحدود العيادة والصلاحيات والعقود إلا تغييرات التعارض المعتمدة، وتوثيق أي تعذر دون تخفيف الفحوص.
- [ ] اختبارات السلوك الخارجية UI/HTTP حسب نطاق التذكرة، وقاعدة dentex_test معزولة للبيانات والترحيلات؛ لا fixtures أو reset على التطوير.
- [ ] النوع والبناء والمعمارية والفحوص المناسبة ومراجعة مقابل main مجلوب حديثًا تشمل الملفات الجديدة، ثم إبقاء السيرفر والقاعدة لفحص المستخدم المحلي قبل PR؛ لا إعادة تهيئة arabesque/2000 أو حساباتها.
- [ ] لا مكتبة Zustand استباقية أو نقل SSE/WebSocket أو تحرير مريض أو حفظ offline أو إعادة تصميم ضمن هذا التقسيم.
