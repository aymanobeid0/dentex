# 02: قائمة المرضى والبحث وقراءة الملف ببيانات متجددة

**What to build:** البحث في الجدول وفتح ملف المريض وقراءة البيانات المحدثة، مع الرجوع إلى قائمة ببحث فارغ وصفحة أولى وبقاء القراءة المحملة أثناء انقطاع الاتصال مع تنبيه.

**Blocked by:** 01 — جلسة المستخدم واللغة عبر أساس البيانات الموحد

**Status:** ready-for-agent

**Execution:** not-started

- [ ] ترحيل قراءة القائمة/الملف إلى Query بمفاتيح المورد ومعاملاته ضمن الجلسة والعيادة؛ إزالة الجلب الموازي لهذين التدفقين.
- [ ] الحفاظ على300ms وEnter/البحث والمسح الفوريين وIME والتركيز والصفحات وإلغاء القديم وتجاهل الرد وJSON المتأخرين.
- [ ] تحديث كل نحو15 ثانية للمعروض فقط عند الظهور والاتصال، والتوقف بالخلفية وعند المغادرة، وإعادة التحقق عند العودة؛ polling لا يتجاوز انتظار نص البحث أو يضاعف الاستعلام.
- [ ] بقاء نسخة العرض أثناء التحديث وعند انقطاع الاتصال مع بيان الحالة، وتمييز القائمة الفارغة والأخطاء ورفض الصلاحية دون كشف بيانات غير مخولة.
- [ ] اختبارات سلوك البحث والمؤقتات والاتصال/الظهور والرجوع والعزل، وتحقق متصفح UI-to-API باللغتين دون إضافة تحرير ملف مريض.

- [ ] اختبارات السلوك الخارجية UI/HTTP حسب نطاق التذكرة، وقاعدة dentex_test معزولة للبيانات والترحيلات؛ لا fixtures أو reset على التطوير.
- [ ] النوع والبناء والمعمارية والفحوص المناسبة ومراجعة مقابل main مجلوب حديثًا تشمل الملفات الجديدة، ثم إبقاء السيرفر والقاعدة لفحص المستخدم المحلي قبل PR؛ لا إعادة تهيئة arabesque/2000 أو حساباتها.
- [ ] لا مكتبة Zustand استباقية أو نقل SSE/WebSocket أو تحرير مريض أو حفظ offline أو إعادة تصميم ضمن هذا التقسيم.
