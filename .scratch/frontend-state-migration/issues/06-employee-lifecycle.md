# 06: إكمال دورة الموظف: الإنشاء والحالة وإعادة تعيين كلمة المرور

**What to build:** إضافة موظف وتفعيل/تعطيل حسابه وإعادة تعيين كلمة مروره عبر السياسة الموحدة، مع تحديث الجدول وانتهاء الجلسات وفق القواعد القائمة ووضوح نتيجة كل إجراء.

**Blocked by:** 04 — تعديل الموظف وأدواره مع منع استبدال تعديل متزامن

**Status:** ready-for-human

**Execution:** complete

- [x] ترحيل ما تبقى من إجراءات الموظف إلى mutations موحدة دون مخزن بيانات موازٍ؛ إعادة قراءة الموارد ذات الصلة بعد تأكيد النجاح.
- [x] استمرار حماية المدير الأخير وحدود التفويض والعزل وإبطال الجلسات وقواعد كلمات المرور؛ الحالة/reset تحتفظ بعقودها الخاصة ولا يفرض عليها محرر سجلات عام.
- [x] تغييرات مؤثرة على أصل تحرير الموظف لا تسمح لحفظ قديم بتجاوز حماية04؛ تُحترم حدود إصدارها المعتمدة دون توسيع غير موثق.
- [x] لا تكرار حفظ تلقائي أو رسالة نجاح مبكرة؛ نتيجة رد مفقود واضحة دون إعادة تعيين كلمة مرور تلقائية.
- [x] حماية مسودات الإنشاء/الحقول السرية من الفقد حسب السياسة دون تخزينها أو تسجيلها أو وضعها في query keys؛ لغتان وتفاعل وصول محفوظ.
- [x] اختبارات UI/HTTP لدورة الموظف والعزل وآخر مدير والجلسات مع سيناريو فشل الرد وفحص محلي.

## شروط الإغلاق لكل تذكرة

- [x] الحفاظ على المعمارية المعتمدة وحدود العيادة والصلاحيات والعقود إلا تغييرات التعارض المعتمدة، وتوثيق أي تعذر دون تخفيف الفحوص.
- [x] اختبارات السلوك الخارجية UI/HTTP حسب نطاق التذكرة، وقاعدة dentex_test معزولة للبيانات والترحيلات؛ لا fixtures أو reset على التطوير.
- [x] النوع والبناء والمعمارية والفحوص المناسبة ومراجعة مقابل main مجلوب حديثًا تشمل الملفات الجديدة، ثم إبقاء السيرفر والقاعدة لفحص المستخدم المحلي قبل PR؛ لا إعادة تهيئة arabesque/2000 أو حساباتها.
- [x] لا مكتبة Zustand استباقية أو نقل SSE/WebSocket أو تحرير مريض أو حفظ offline أو إعادة تصميم ضمن هذا التقسيم.
