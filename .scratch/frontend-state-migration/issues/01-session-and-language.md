# 01: جلسة المستخدم واللغة عبر أساس البيانات الموحد

**What to build:** الدخول بالهوية الصحيحة، عرض بيانات الجلسة، استمرار اللغة والاتجاه، والخروج/انتهاء الجلسة دون ظهور بيانات حساب سابق. يدخل TanStack Query والطلبات المشتركة من تدفق مستخدم فعلي وتبقى الشاشات غير المرحلة عاملة.

**Blocked by:** None (can start immediately)

**Status:** ready-for-human

**Execution:** ready-for-human — technical verification passed; local user review pending

- [x] الهوية وبياناتها القادمة من API تدار عبر Query، واللغة/الاتجاه في سياق محدود مع استمرار حفظ اللغة؛ لا Context يجمع بيانات الميزات أو Zustand استباقي.
- [x] الطلبات المشتركة تصنف أخطاء الشبكة/HTTP/الدخول/انتهاء الجلسة وتستقبل إشارة إلغاء القراءات، وتفصل النتيجة غير المؤكدة للكتابة عن الفشل المؤكد؛ لا إعادة إرسال تلقائية للكتابات.
- [x] لا تعطيل صامت لانتهاء الجلسة في الشاشات القديمة؛ تُدمج دورة الجلسة المشتركة مع حالة الهوية الحالية ومسح الشاشات التابعة لها.
- [x] cache في الذاكرة مع هوية جلسة وعزل عيادة، وإلغاء القراءات وإهمال الردود عند تبدل الجلسة؛ لا بيانات حساسة مخزنة بشكل دائم أو مفاتيح تتضمن كلمات المرور.
- [x] الدخول والخروج وقواعد cookie الحالية محفوظة، مع اختبار دخول حسابين متتابعين ورد متأخر وانتهاء الجلسة وفشل الدخول؛ العربية والفرنسية والاتجاه وRadix سليمة.
- [x] تهيئة سياسة القراءة/retry ومراقبة الظهور والاتصال تُستخدم في جلب الهوية المعروضة فعليًا، دون تشغيل جلب خلفي لكل موارد التطبيق.

## شروط الإغلاق لكل تذكرة

- [x] الحفاظ على المعمارية المعتمدة وحدود العيادة والصلاحيات والعقود إلا تغييرات التعارض المعتمدة، وتوثيق أي تعذر دون تخفيف الفحوص.
- [x] اختبارات السلوك الخارجية UI/HTTP حسب نطاق التذكرة، وقاعدة dentex_test معزولة للبيانات والترحيلات؛ لا fixtures أو reset على التطوير.
- [x] النوع والبناء والمعمارية والفحوص المناسبة ومراجعة مقابل main مجلوب حديثًا تشمل الملفات الجديدة، ثم إبقاء السيرفر والقاعدة لفحص المستخدم المحلي قبل PR؛ لا إعادة تهيئة arabesque/2000 أو حساباتها.
- [x] لا مكتبة Zustand استباقية أو نقل SSE/WebSocket أو تحرير مريض أو حفظ offline أو إعادة تصميم ضمن هذا التقسيم.
