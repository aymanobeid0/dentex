# 04: تعديل الموظف وأدواره مع منع استبدال تعديل متزامن

**What to build:** عرض الموظفين وفتح تعديل موظف وحفظ بياناته وأدواره، مع احتفاظ المدير بمسودته إذا تغير السجل ورفض الحفظ المتعارض ذريًا بدل استبدال تعديل مدير آخر.

**Blocked by:** 01 — جلسة المستخدم واللغة عبر أساس البيانات الموحد

**Status:** ready-for-human

**Execution:** complete — تنفيذ محلي؛ ينتظر فحص المستخدم قبل PR

- [x] ترحيل قراءات الموظفين وكاتالوج الأدوار اللازمة للنموذج وكتابة تعديل بيانات الموظف وإسناد أدواره؛ باقي إجراءات دورة الموظف تستمر حتى التذكرة06 دون كسر الشاشات.
- [x] توثيق عقد الإصدار وحدود تغييره وخطأ التعارض وخطة ترحيل البيانات القائمة قبل التنفيذ ضمن طبقات الخادم الحالية، ثم تنفيذ الإصدار والفحص الذري وربطهما بالنموذج في التذكرة نفسها.
- [x] رفض إصدار قديم/مفقود/غير صالح حسب العقد دون كتابة جزئية أو فتح تجاوز، مع إبقاء العزل وإعادة فحص الصلاحيات وقواعد المدير النشط.
- [x] التحديث الدوري للبيانات المعروضة لا يمسح المسودة؛ ينبه بتغيير الأصل. مراجعة أحدث نسخة تتطلب إجراء صريحًا قبل إعادة الحفظ، دون دمج أو استبدال أو ترقية إصدار صامتة.
- [x] تنبيه تجاهل المسودة وضوابط الكتابة غير المؤكدة والقراءة offline والعربية/الفرنسية وRadix وفق النمط المشترك؛ يعاد استخدام مساعدات موجودة عند توفرها، وتُبنى حاجة التذكرة الحالية دون انتظار تذكرة غير حاجبة.
- [x] تحقق HTTP بكتابتين فعليتين من الإصدار نفسه، ثم UI لسلوك التعارض والمراجعة؛ ترحيل جديد على قاعدة اختبار معزولة مع حفظ بيانات التطوير وقواعد الجلسات.

## شروط الإغلاق لكل تذكرة

- [x] الحفاظ على المعمارية المعتمدة وحدود العيادة والصلاحيات والعقود إلا تغييرات التعارض المعتمدة، وتوثيق أي تعذر دون تخفيف الفحوص.
- [x] اختبارات السلوك الخارجية UI/HTTP حسب نطاق التذكرة، وقاعدة dentex_test معزولة للبيانات والترحيلات؛ لا fixtures أو reset على التطوير.
- [x] النوع والبناء والمعمارية والفحوص المناسبة ومراجعة مقابل main مجلوب حديثًا تشمل الملفات الجديدة، ثم إبقاء السيرفر والقاعدة لفحص المستخدم المحلي قبل PR؛ لا إعادة تهيئة arabesque/2000 أو حساباتها.
- [x] لا مكتبة Zustand استباقية أو نقل SSE/WebSocket أو تحرير مريض أو حفظ offline أو إعادة تصميم ضمن هذا التقسيم.
