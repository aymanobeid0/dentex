# تجهيز staging وCI سريع — 2026-11-03

Status: closed

طلب المستخدم Dockerfile وبيئة staging مع قاعدة بيانات على Dokploy وVPS، بالنطاق المصحح `dentex.itlabservice.com`. أكد أن النشر يدوي من Dokploy بعد نجاح CI، لتجنب عمل نشر وبناء صور إضافي في CI. المهمة تجهيز الملفات والتحقق محليًا؛ لم يطلب نشر الخدمة الآن أو رفع تغييرات Git المتراكمة.

## النطاق

- صورة تطبيق متعددة المراحل وصورة ترحيلات منفصلة، مع حفظ نموذج التطبيق الموحد والخادم الحالي. HOST إعداد تشغيل؛ لا تعديل في طبقات الميزات أو واجهاتها أو قواعد المعمارية.
- Compose staging بقاعدة مستقلة وvolume دائم، وترحيلات قبل بدء التطبيق، وHTTP داخلي خلف Dokploy HTTPS دون منافذ مضيف عامة.
- cache npm وطبقات Docker محدودة السياق، وإلغاء CI القديم وبناء وفحص معماري متوازيين مع بقاء جميع الاختبارات ومانع التخطي.
- لا webhook أو auto deploy أو رفع إلى registry أو بيانات تطوير أو حسابات افتراضية في staging.
- الإعداد اليدوي والمتغيرات والدخول الأول موثقة في `docs/staging-dokploy.md`.

## أدلة التحقق

- بُني runtime وmigrations فعليًا على Docker Linux المحلي. مستخدم runtime هو node، وUID=1000؛ تحققت غيبة prisma CLI وtypescript وvite وvitest وملف .env من صورة التشغيل. حجم الصورة المحلي غير المضغوط 515,198,290 بايت.
- سياق البناء الكامل نحو 441 كيلوبايت، وإعادة بناء runtime دون تغيير الملفات استغرقت 7.5 ثانية باستخدام الطبقات المخزنة. هذا قياس Docker Desktop محلي، لا وعد بزمن أول بناء أو زمن VPS؛ صورة migrations الأولى أكبر لأنها تحمل أدوات Prisma ضمن اعتماديات البناء.
- شُغّل Compose باسم اختبار مستقل dentex-staging-qa-20261103، مع قاعدة dentex_staging وvolume مؤقتة تخصه. طُبقت الترحيلات الثلاثة بنجاح قبل بدء app، وأصبح database وapp بحالة healthy.
- أضيف override خارج المستودع بمنفذ localhost وشبكة qa_proxy غير داخلية لمحاكاة شبكة Dokploy/Traefik. الشبكة private وحدها مقصودة لاتصال البيانات، ولا تتيح الوصول الخارجي؛ لهذا يجب أن تظهر شبكة التوجيه الإضافية في Preview Compose.
- نجح فحص HTTP من خارج حاوية app: الواجهة الثابتة، ودخول مدير برنامج وهمي، وإنشاء عيادة بمديرها ذريًا، ودخول العيادة، وتسجيل مريض وقراءة ملفه. لا حسابات أو كلمات مرور افتراضية مضمّنة في ملفات staging.
- أُعيد تشغيل Compose على نفس volume؛ أفاد migrate بعدم وجود ترحيلات معلقة، وبقي سجل الترحيلات الثلاثة والمريض التجريبي محفوظين. ثم حُذف مشروع الاختبار وحجمه وشبكاته فقط. لم تُستخدم قاعدة التطوير لهذا الفحص.
- نجح npm run build وnpm run check:architecture، ونجحت 93 حالة في 22 ملفًا عبر node scripts/test-local.mjs على dentex_test، دون تخطي.
- تحقق تركيب Compose وCI YAML، وتأكدت بقاء الأوامر والفحوص وعدم وجود نشر تلقائي. جُرب نص Bash الفعلي لخطوة التوازي بحالات نجاح الاثنين وفشل أحدهما وفشل الاثنين؛ يُرجع فشلًا عند أي إخفاق، ولا يسمح بخطوة الاختبارات بعده.

## حدود التنفيذ

لم يُنشر شيء على VPS أو يُغيّر DNS أو إعداد Dokploy أو GitHub. قرئت نسخة Dokploy المتصلة فقط (v0.30.10)، واعتمد الإعداد على وثائق Dokploy الرسمية لربط النطاق وإضافة الشبكة وCompose العادي. لا يعني هذا تشغيل الخدمة حيًا أو نجاح شهادة TLS أو تنفيذ workflow على GitHub. النشر يدوي بعد رفع التغييرات ونجاح فحص commit المقصود، وفق دليل docs/staging-dokploy.md.
