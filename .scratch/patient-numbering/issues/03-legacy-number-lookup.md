# 03: مراجعة الرقم القديم لمدير العيادة فقط

**What to build:** من إجراء خاص في شاشة المرضى يدخل مدير العيادة رقم ملف قديمًا، فيرى اسم المريض ورقمه الجديد ورابط ملفه، دون خلط البحث القديم بالبحث المعتاد أو كشف أرقام عيادة أخرى.

**Blocked by:** 01 — تسجيل المريض بترقيم مستقل ونقل الأرقام الموجودة بأمان. لا تعتمد على02.

**Status:** closed

**Execution:** complete

- [x] إجراء فردي لمدير العيادة في شاشة المرضى، لا جدول شامل أو تصدير أو واجهة لبقية الأدوار. يستخدم سجل التحويل المحفوظ دون تخمين الربط أو إعادة ترقيم جديدة.
- [x] إدخال الرقم القديم يعيد اسم المريض ورقمه الجديد ومعرّفه اللازم لفتح الملف؛ فتح الرابط يصل إلى الملف نفسه بعد الانتقال.
- [x] البحث المعتاد يعتمد الأرقام الجديدة فقط، حتى إذا طابق رقم جديد رقمًا قديمًا لمريض آخر. لا جمع صامت للنتائج القديمة والجديدة أو فتح ملف بالتخمين.
- [x] عيادة البحث من الجلسة وحدها، وصلاحية مدير العيادة الحالية تُفحص في كل طلب. ترفض أدوار الطبيب والاستقبال ومدير البرنامج، ولا تكفي صلاحية قراءة المرضى وحدها.
- [x] حالة عدم وجود مرجع قديم واضحة للملفات الجديدة وغير الموجودة وخارج العيادة دون كشف تفاصيل عيادات أخرى، مع تحقق الإدخال ورسائل التحميل والخطأ والانقطاع.
- [x] لا تظهر نتيجة محفوظة أو استجابة متأخرة بعد سحب دور المدير أو تبديل الجلسة. القراءة وإلغاء طلباتها ضمن سياسة بيانات الخادم القائمة، ودون تخزين دائم أو جلب مستمر بعد إغلاق النافذة.
- [x] تبقى الخريطة محفوظة ما دام الملف موجودًا، دون حذف زمني أو تغيير بيانات الملف أو منح صلاحيات جديدة لأدوار أخرى.
- [x] النافذة وتسمياتها واتجاهها وتركيزها واستعادة التركيز ولوحة المفاتيح تعمل فعليًا بالعربية والفرنسية باستخدام المكونات المعتمدة، دون إعادة تصميم شاشة المرضى.
- [x] اختبارات من الواجهة والطلبات: بحث قديم صحيح وفتح الملف الجديد، اصطدام قديم بجديد، رقم غير موجود وملف بلا مرجع قديم، عزل عيادتين، رفض غير المدير، سحب الدور ورد متأخر، وإغلاق النافذة واستمرار البحث المعتاد دون كشف القديم لبقية المستخدمين.
- [x] إكمال [معايير الإغلاق المشتركة](../map.md#معايير-الإغلاق-المشتركة)، دون تعليق هذه الاختبارات على مهمة لاحقة.
