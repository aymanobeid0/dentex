## حدود الأدوات — حسمها المستخدم

- TanStack Query هو المرجع الوحيد لنسخ بيانات API في الواجهة، بما فيها هوية المستخدم وصلاحياته؛ لا نسخ موازية لهذه البيانات في Context أو Zustand.
- useState للحالة المحلية وuseReducer لتدفقات محلية مركبة عند الحاجة. مسودات النماذج مستقلة عن البيانات الواردة من الخادم.
- Context لسياقات محددة وإعدادات مشتركة مثل اللغة والاتجاه؛ لا AppContext يجمع كل حالات الميزات.
- Zustand عندما تظهر حاجة فعلية لحالة عميل مشتركة معقدة. لا تثبيت أو store عام استباقي. لا تختار هذه الوثيقة تفاصيل مخطط الأسنان الذي لم ينفذ بعد.
- Radix Primitives لسلوك المكونات وفق docs/ui-primitives.md، ويظل مستقلًا عن ملكية بيانات الخادم.

## التحديث والتصفح — حسمهما المستخدم

- إعادة جلب دورية كل نحو15 ثانية للبيانات المشتركة المعروضة فقط في الشاشة الحالية عند ظهور التبويب والاتصال. لا polling لبيانات الشاشات غير المفتوحة أو بالخلفية. إعادة تحقق عند العودة والاتصال، وتحديث الموارد المتأثرة بعد نجاح الحفظ.
- الآلية المعتمدة لهذا الهدف polling عبر TanStack Query؛ لا حاجة لاتصال SSE/WebSocket لتحقيق القرار الحالي.15 ثانية دورية محاولة وليست ضمان زمن وصول عند تعطل الشبكة أو بطء الخادم.
- لا تعديل تلقائي لمسودة النموذج عند وصول بيانات أحدث؛ تُحفظ المسودة ويظهر تنبيه إذا تغير أصلها. بقية العرض يمكنه استخدام بيانات الخادم الأحدث.
- عند العودة من ملف المريض إلى القائمة: بحث فارغ وصفحة أولى. البحث المباشر يبقى300ms من آخر تغيير؛ Enter والمسح فوريان والإلغاء/تجاهل الردود القديمة إلزاميان. سياسة cache لا تعيد البحث السابق للواجهة.
- عند مغادرة نموذج معدل: خيار البقاء أو المغادرة مع تجاهل المسودة، دون تخزين دائم. يشمل التصميم التنقل الداخلي وتحذير إعادة التحميل/الإغلاق بالقدر الذي يسمح به المتصفح، دون ضمان منع إغلاق قسري.
- دون اتصال يمكن قراءة ما حُمّل داخل الجلسة مع تنبيه واضح بعدم حداثته. لا اعتبار لحفظ محلي كحفظ ناجح في الخادم، ولا صف كتابة مؤجلة للعمل دون اتصال.

## حماية التعارض — وافق المستخدم على نطاقها

تُنفذ تذكرة مستقلة لحماية تعديل بيانات الموظفين وأدوارهم ومنح الأدوار، بإصدار سجل وفحص ذري لحظة الحفظ. تغيير سجل متأثر يجعل الحفظ المبني على نسخة قديمة يفشل بتعارض واضح دون استبدال تعديل الآخر. تحتفظ الواجهة بالمسودة وتطلب مراجعة النسخة الأحدث قبل محاولة حفظ جديدة؛ لا دمج أو استبدال تلقائي.

المطلوب تعديل العقود والترحيل اللازم مع حماية العيادة والصلاحيات والمعاملات الموجودة. تنظيم route/controller/service/repository واختبارات المعمارية باقٍ كما هو؛ لا استثناء. credentialVersion للجلسة لا يُستخدم بدل إصدار تحرير السجل. تصميم الإصدار وحدود زيادة إصداره وتعبير خطأ التعارض توثق في مواصفة التذكرة قبل التنفيذ.

لا يوجد حاليًا تعديل ملف مريض: الإنشاء والعرض هما العقد القائم. تُطبق قاعدة التعارض عند بناء ميزة تحرير ملف المريض لاحقًا، دون إدخالها ضمن هذا الانتقال. عمليات تغيير كلمات المرور وإبطال الجلسات تحافظ على عقودها وقواعدها الخاصة؛ ليست محرر سجل عام.

## ضوابط مكملة معتمدة

- cache في الذاكرة فقط، دون حفظ بيانات المرضى أو الموظفين أو المنح في localStorage/IndexedDB. حفظ تفضيل اللغة القائم مستمر؛ القراءة offline لا تعني حفظًا دائمًا أو عملًا بعد إعادة التحميل.
- عزل cache بحسب هوية الجلسة والعيادة ونوع المورد ومعاملات الاستعلام، مع إلغاء الطلبات ومسح بيانات الجلسة عند الخروج/انتهائها أو تبديل الهوية. لا استجابة متأخرة تعيد بيانات جلسة سابقة. يبقى الخادم مرجع الصلاحيات وعزل العيادات.
- retry محدود للقراءات عند الأخطاء المؤقتة فقط؛ لا تكرار تلقائي لفشل الدخول أو رفض الصلاحية أو التحقق أو التعارض. الحفظ ينتظر تأكيد الخادم؛ لا نجاح تفاؤلي ولا إعادة إرسال تلقائي لطلبات الكتابة.
- إذا انقطع الرد بعد إرسال حفظ، لا نزعم النجاح أو الفشل المؤكد: يُعرض تعذر التأكد وتُراجع بيانات الخادم قبل إعادة محاولة قد تكرر الإنشاء. ضمان منع التكرار بآلية idempotency مستقلة لا يُفترض أنه موجود.
- طلبات HTTP ومعالجة الأخطاء والجلسة مشتركة، وhooks الاستعلام/الحفظ وquery keys تملكها الميزة المعنية. المكونات تعرض البيانات وتحتفظ بحالة واجهتها؛ لا إعادة بناء مدير cache موازٍ.

## خطة الانتقال والتحقق

حسم المستخدم شمول جميع الشاشات الحالية بترحيل على تذاكر متتابعة، مع نمط ملزم للميزات المستقبلية. تسلسل التخطيط المعتمد: أساس Query والجلسة والطلبات؛ المرضى والبحث؛ حماية التعارض في الخادم؛ الموظفون والأدوار؛ العيادات ومديروها والحساب الشخصي؛ ثم مراجعة شاملة للحدود والتوثيق. المواصفة والتذاكر التفصيلية أُعدت واعتمدت ونُشرت؛ حالة التنفيذ والحواجز في فهرس التذاكر المرتبط أدناه.

تُختبر حدود cache والجلسة، توقف polling واستئنافه، الردود المتأخرة، بقاء المسودات، التنقل، الحفظ المؤكد وحالات التعارض المتزامنة والعزل. يُحفظ العقد الحالي للبحث والتصميم واللغتين وRadix، ويُجرى فحص UI-to-API. بيانات التطوير الدائمة لا يعاد تهيئتها؛ الاختبارات على dentex_test معزولة. بعد كل تذكرة تُترك البيئة المحلية للمستخدم قبل PR وفق docs/development-database.md. المراجعة مقابل main مجلوب حديثًا.

أكد المستخدم في النموذج النهائي: «أعتمد الصيغة النهائية والضوابط المكملة؛ انتهى نقاش القرار». هذه الوثيقة مرجع القرار، وليست إعلان تنفيذ. لا تغييرات كود أو حزم أو API أو schema نُفذت خلال جلسة القرار، ولا تُعد الموافقة على الفهم وحدها طلبًا لبدء التنفيذ.

نُشرت المواصفة التنفيذية للنطاق المعتمد في [.scratch/frontend-state/spec.md](../.scratch/frontend-state/spec.md) بحالة ready-for-agent بتاريخ2026-11-04، مع بند متابعة في المتتبع المحلي. النشر لا يبدأ التنفيذ.

اعتمد المستخدم تقسيم التنفيذ إلى9 تذاكر بتاريخ2026-11-04؛ نُشرت في [فهرس التذاكر](../.scratch/frontend-state-migration/map.md)، مع بقاء المواصفة وبند المتابعة الأصليين مرجعًا ودون تعديل الأب أو بدء تنفيذ.

## تطبيق النمط في الميزات المقبلة

تبقى قرارات الملكية والعزل أعلاه هي المرجع. التنفيذ الحالي مُحصر في [حصر09](../.scratch/frontend-state-migration/09-inventory.md)، وقصصه في [تغطية44](../.scratch/frontend-state-migration/09-coverage.md):

- تملك الميزة عملياتHTTP فيapi.ts ومفاتيح مواردها وhooks القراءة والحفظ؛ تستخدمuseApi والنطاق المشترك، وتعلن صادراتها المختارة عبرindex.ts. تبقىauth مالكة الهوية ودورةالجلسة، وapp يركّب callbacks بين الميزات.
- تستخدم القراءات المعروضةuseDisplayedQuery أو سياسة المرضى للبحث والملف؛ المفاتيح تشمل نطاق الجلسة ومعاملات القراءة فقط، ولا كلمات مرور. توقف القراءة الدورية عند مغادرة الشاشة أو الإخفاء أو الانقطاع؛ المراجعة اليدوية منفصلة عنpolling ولا يعادل تحديث القائمة تأكيد الحفظ.
- تمر الكتابات عبرuseMutation بلاretry أو صفoffline، وتنتظر تأكيد العقد وتحدّث الموارد ذات الصلة. العمليات التي تحمل أسرارًا تستخدمgcTime0 وreset بعدالاستقرار. يمنع إرسال جارٍ أوانقطاع الاتصال طلبًا إضافيًا؛ ولا تُعاد الكتابة عندعودة الاتصال.
- تبقى المسودة محلية ومستقلة عنQuery، معuseDraftGuard وDiscardDraftDialog وbeforeunload فيحدوده. يحفظ التعارض أوالردالمفقود المسودة ويُعرض بوضوح،ولا يُحسم تلقائيًا. كلماتالمرور ليست محرر سجلات عامًا ولاقراءةالقائمة تثبتتغييرها.

المساعدات أدوات لتنفيذ القرار وليست ضمانًا للوصول أوالتفرد أوذرية الخادم. تفويضالخادم وعزل العيادة والمعاملات وفحص الإصدار هيالضمانات ذاتالصلة. يجب التحقق من السلوك منالشاشة وHTTP والمتصفح وفق العقود؛ لامخزنعام أوZustand أوSSE أوحفظدائم استباقي.
