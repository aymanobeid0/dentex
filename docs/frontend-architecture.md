# معمارية الواجهة المعتمدة

اعتمد المستخدم في 2026-11-04 [مقترح تنظيم الواجهة](../.scratch/frontend-architecture/audit-and-proposal.md) بقوله: «انا موافق على ترتيب الكود الذي اقترحته». يشمل الإذن إعادة تنظيم الواجهة الحالية وفصل مسؤولياتها وفحص اعتمادياتها، مع حفظ السلوك والتصميم والعقود. لا يشمل تنفيذ انتقال الحالة 03–09 أو تغيير معمارية الخادم.

## التنظيم والملكية

```text
client/
  entry.tsx
  app/                    # تركيب التطبيق وproviders والتنقل والتخطيط
  features/
    auth/
    clinics/
    employees/
    roles/
    account/
    patients/
  shared/
    api/                  # النقل والأخطاء والإلغاء وعزل الطلبات
    query/                # عميل Query والنطاق وإشارات المتصفح
    i18n/                 # اللغة والترجمات
    styles/               # الأساس والأنماط المشتركة
  ui/                     # Radix والمكونات العامة
```

كل ميزة تملك صفحاتها ومكوناتها وhooks التفاعل وعمليات HTTP وأنواعها واستعلاماتها بحسب الحاجة. الصفحات تركّب تدفق الميزة؛ النماذج والجداول والملف مكونات مستقلة، والطلبات داخل `api.ts`. تعلن `index.ts` صادرات مختارة للمستهلك الخارجي، مع استيرادات داخلية صريحة. لا مجلدات فارغة أو طبقات خادم مفروضة على React.

تملك `auth` نوع الحساب ودورة الجلسة والهوية والدخول والخروج. تربط النقل ونطاق Query بالبنية العامة، بينما تستخدم الميزات الأخرى `shared/api` و`shared/query` دون اعتماد على auth. تبقى DTOs وبيانات المجال داخل ميزاتها، ولا توضع في Context عام.

يملك `app/navigation.ts` نوع التنقل. يركّب App الصفحات والصلاحيات وcallbacks المشتركة؛ لا ينفذ CRUD للميزات. تبقى حالة مسودة إنشاء العيادة وقائمتها محفوظة عند الانتقال إلى الحساب، ويُلغى نطاق البيانات عند استبدال الجلسة كما كان.

## الاعتماديات والفحص

الاتجاه `app → features → shared/ui`. لا تستورد `shared` أو `ui` من `app/features`، ولا تستورد ميزة من ميزة أخرى. ينسق app التفاعلات المشتركة عبر الواجهات أو callbacks. يمنع المستهلك الخارجي من الوصول إلى ملفات الميزة الداخلية، وتمنع الدورات والواردات غير المحلولة.

يشغّل `npm run check:frontend-architecture` قواعد `.dependency-cruiser.frontend.cjs` المستقلة في CI. تثبت اختبارات CLI قبول التركيب المسموح ورفض تجاوز الحدود والدورات والواردات غير المحلولة. يبقى `check:architecture` للخادم وقواعده دون تغيير.

تكتب TSX بشكل مقروء. تستخدم مهارتا `vercel-react-best-practices` و`codebase-design` وفق AGENTS.md، مع واجهات محدودة ومراجعة أثر الصادرات على الحزمة. قواعد Vercel المناسبة لـReact/Vite تطبق ضمن قرارات المشروع؛ لا يعني التنظيم إضافة Next.js أو تغيير آلية إدارة الحالة.

## الأنماط والسلوك

يركّب `app/styles.css` الأنماط المشتركة وأنماط التخطيط والميزات وRadix. يحتفظ `shared/styles/forms.css` بقواعد `.clinic-form` القديمة لأنها مستخدمة أيضًا في الموظفين والحساب؛ الاسم القديم لا يمنح ميزة العيادات ملكية هذه القواعد. تبقى أسماء الأصناف والتصميم والعقود، ويُتحقق من أثر ترتيب CSS في المتصفح.

تبقى React/Vite وTanStack Query وAR/FR وRTL/LTR وRadix ودورة الجلسة والـcache في الذاكرة كما اعتمدت. استخراج الكتابة القائمة لا يرحلها إلى Query أو يضيف معالجة تعارض خارج التذاكر المكلفة.

التحقق يشمل الأنواع والاختبارات المستهدفة ثم كامل الاختبارات والبناء وفحص الخادم والواجهة ومراجعة main مجلوب حديثًا. يفحص المتصفح التركيز ولوحة المفاتيح والتصميم والبحث وIME والانقطاع بحسب التدفقات المتأثرة. تحفظ قاعدة التطوير وحساباتها وvolume وبيانات الفحص، وتبقى UI5173 وAPI3000 والقاعدة55460 للمستخدم قبل PR.

حالة التنفيذ في [التذكرة](../.scratch/frontend-architecture/issues/01-reorganize-client.md) وأدلته في [سجل التحقق](../.scratch/frontend-architecture/verification.md). أي تغيير خارج هذا التنظيم يعود إلى المستخدم قبل التطبيق.
