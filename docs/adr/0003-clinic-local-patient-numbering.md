# ترقيم ملفات مستقل لكل عيادة مع تحويل المراجع القديمة

الحالة: معتمد في2026-11-04 بقول المستخدم «تم الاعتماد» بعد [المقابلة](../../.scratch/patient-numbering/design.md) وعرض [خطة التطبيق والتوسعة المحددة](../../.scratch/patient-numbering/proposal.md). التنفيذ لم يبدأ.

العداد المشترك يكشف نشاطًا تقريبيًا لعيادات أخرى عبر أرقام الملفات الظاهرة. اختار المستخدم عدادًا مستقلًا لكل عيادة وإعادة ترقيم الملفات الموجودة من١ حسب ترتيب الرقم القديم، مع حفظ مرجع تحويل دائم ما دام الملف موجودًا، مقيد بمدير العيادة عبر بحث فردي. يحفظ ذلك هوية المريض وروابطه ويزيل اعتماد الأرقام الجديدة على نشاط العيادات الأخرى، مقابل كلفة انتقال للمراجع السابقة وتوقف كتابة موثق مع نسخة احتياطية نهائية وتحقق قبل فتح التطبيق.

للعيادة الجديدة بداية١ افتراضيًا، يختار مدير البرنامج غيرها عند إنشائها. لا تعاد الأرقام بعد الأرشفة أو سنويًا، والفجوات مسموحة. ترقيم الفواتير مستقل لكل عيادة عند تنفيذها لاحقًا، ولا تُنفذ الفواتير ضمن هذه المرحلة.

تملك وحدة المرضى العدّاد وسجل التحويل، وتتوسع واجهتها المعلنة لتهيئة العدّاد ضمن معاملة إنشاء العيادة القائمة. هذه التوسعة المحددة معتمدة، مع بقاء طبقات الخادم وملكية المعاملات وحدود الوحدات وفحوصها. لا تمنح الموافقة إذنًا باستثناء معماري أو حذف بيانات أو إعادة تهيئة أو بدء نشر.
