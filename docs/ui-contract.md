# عقد الشاشات والخادم

## الحالة والمرجعية

اعتمد المستخدم نموذج الدخول مرجعًا بصريًا، واعتمد محتوى لوحتي العيادة ومدير البرنامج أدناه. تجمع الوثيقة محتوى الشاشات من المواصفة والتذاكر، ولا تضيف عمليات جديدة إلى نطاق المنتج. أي توسع لاحق في المحتوى يحتاج قرارًا مستقلًا.

- المرجع الوظيفي: مواصفة الحسابات في المتتبع المحلي وقرارات المستخدم الأحدث.
- المرجع البصري: نموذج الدخول المعتمد ثم دليل التصميم والرموز والصور، مع أولوية تعديلات المستخدم الأحدث.
- النموذج ملف عرض فقط: رسائل نجاحه لا تمثل مصادقة حقيقية، والبطاقة التعريفية فيه محتوى تعريفي وليست بيانات API أو وعدًا بأن الوحدات المستقبلية منفذة.

## قواعد الربط

- قبل تنفيذ كل تذكرة، يُحدد عقد عملياتها: مدخلات الطلب، بيانات الاستجابة المسموح بها، حالات النجاح والخطأ والصلاحيات. يُنفذ العقد في الطرفين ويُختبر من خلال HTTP، دون إعادة تصميم النطاق المتفق عليه.
- كل قيمة تُعرض بوصفها بيانات فعلية تأتي من الخادم. بيانات التجربة منفصلة عن الإنتاج، ولا تُستخدم قيم وهمية لإخفاء فشل الطلب.
- لا تُعاد كلمات المرور أو تجزئاتها في استجابات القوائم والتفاصيل، ولا يصل JWT إلى JavaScript.
- الخادم يفرض نطاق العيادة وصلاحيات العملية؛ إخفاء زر في الواجهة لا يكفي. تعديلات الدور والتعطيل وإبطال الرموز تنعكس عند الطلب التالي.
- تُعرض حالات التحميل، والقائمة الفارغة، وأخطاء الحقول، والتعارض، ومنع الوصول، وانتهاء الدخول، وتعذر الاتصال بوضوح في اللغتين. لا تُعرض عملية ناجحة قبل تأكيد الخادم، وتُمنع الإرسالات المكررة أثناء التنفيذ.
- لا تُضاف روابط واتساب أو استعادة ذاتية أو تسجيل عام أو وظائف مستقبلية اعتمادًا على صور التصميم القديمة.

## محتوى اللوحات المعتمد

- إطار الشاشات الداخلية موحّد في لوحتي العيادة ومدير البرنامج: شريط جانبي قابل للطي وشريط تنقل علوي (Navbar)، ويتبدل المحتوى داخل مساحة العمل دون إعادة بناء الإطار لكل شاشة. شاشة تسجيل الدخول مستقلة عن هذا الإطار.
- يظهر الشريط الجانبي يمينًا بالعربية ويسارًا بالفرنسية. على المكتب يتحول عند الطي إلى شريط أيقونات مع تسميات مساعدة وأسماء وصول؛ وعلى الهاتف يظهر كقائمة جانبية يمكن فتحها وإغلاقها دون حجب المحتوى بصورة دائمة.
- زر الطي موجود وواضح وقابل للاستخدام بلوحة المفاتيح، ويعبّر عن حالة الفتح عبر `aria-expanded`. يحافظ التنقل بين الشاشات على حالة الطي خلال استخدام التطبيق.
- يتيح الشريط العلوي تبديل اللغة والوصول إلى الحساب والخروج. لا تُضاف عناصر بحث أو إشعارات بلا وظيفة منفذة.

- تعرض لوحة العيادة في المرحلة الأولى: الموظفين، والأدوار والصلاحيات، وحسابي فقط؛ لا تظهر أقسام المرضى أو المالية أو أي أقسام غير منفذة.
- تعرض لوحة مدير البرنامج قائمة العيادات باسم العيادة ورمزها، مع إنشاء عيادة وإدارة مديريها؛ دون إحصاءات أو اشتراكات لم تُطلب.

## مسائل تشغيلية غير محسومة
- مكان الاستضافة وإجراء التحقق التشغيلي لاستعادة وصول صاحب العيادة خارج قرار ترتيب الشاشات؛ لا يُفترض أنهما محسومان.

## معيار إتمام شاشة

1. مطابقة قواعد النموذج المعتمد: حدود رفيعة فاتحة بلا حلقة زرقاء أو حدود متراكبة؛ أيقونات Lucide؛ حماية لون الحقول عند autofill.
2. عرض العربية RTL والفرنسية LTR بنفس المحتوى، مع ترجمة التسميات والأخطاء وأسماء الحالات؛ عزل الرموز والأرقام اتجاهيًا.
3. عمل الإجراءات المرئية عبر الخادم الحقيقي ضمن التذكرة، مع اختبارات الصلاحيات والعزل وحالات الخطأ الأساسية.
4. فحص الاستجابة ولوحة المفاتيح والتركيز والأيقونات ذات التسميات المقروءة، ومقارنة الشاشة بالمرجع بصريًا؛ إذا تعذر الفحص يُسجل القيد ولا يُدعى اكتماله.


## عقد إنشاء العيادة (التذكرة 02)

`POST /api/clinics` يتطلب جلسة مدير البرنامج وفحص المصدر. يقبل JSON بالحقول `name` و`code` و`managerName` و`managerUsername` و`managerPassword`. الرمز نص من أربعة أرقام؛ تُزال المسافات المحيطة بالأسماء واسم المستخدم، وتبقى حالة الأحرف مميزة. عند النجاح يعيد 201 مع `id` و`name` و`code` فقط، ويُنشئ المدير والأدوار الثلاثة ضمن معاملة واحدة. يعيد 400 للمدخلات غير الصالحة، و409 مع `duplicate_code` للرمز المكرر، و401 لغياب جلسة مدير البرنامج أو عدم صلاحيتها، و403 للمصدر غير الموثوق، و500 لفشل الخادم دون كشف البيانات الحساسة. لا يعيد كلمة المرور أو تجزئتها.


## عقد دخول العيادة (التذكرة 03)

`POST /api/auth/clinic/login` يقبل `code` (نص من أربعة أرقام) و`username` و`password`، ويتحقق من مصدر الطلب وحد المحاولات. يعيد 200 وهوية الحساب والعيادة وأدواره وصلاحياته دون أسرار، مع Cookie الجلسة المحمية؛ ويرد 400 للمدخلات غير الصالحة، و401 برسالة موحدة للبيانات غير الصحيحة أو الحساب المعطل، و403 للمصدر غير الموثوق، و429 عند تجاوز الحد. `GET /api/auth/me` يقرأ الحساب وحالته وأدواره وصلاحياته الحالية من قاعدة البيانات عند كل طلب ويعيد 401 للجلسة المنتهية أو الملغاة. تُشتق العيادة من المستخدم المصادق عليه لا من معرّف يرسله العميل. جلسة العيادة لا تتيح واجهة إدارة البرنامج؛ تسجيل الخروج يمسح Cookie الجهاز الحالي.

## عقد الموظفين (التذكرة 04)

`GET /api/clinic/roles` و`GET /api/clinic/employees` و`GET /api/clinic/employees/:id` تعرض الأدوار والموظفين في عيادة الجلسة فقط. `POST /api/clinic/employees` يقبل `name`, `username`, `password`, `roleIds`، و`PUT /api/clinic/employees/:id` يقبل الحقول نفسها عدا كلمة المرور. يعيد الخادم الاسم واسم المستخدم والحالة والأدوار دون كلمات المرور أو تجزئاتها. تُزال المسافات المحيطة بالأسماء وأسماء المستخدمين مع تمييز حالة الأحرف، وتفرد أسماء المستخدمين ضمن العيادة. تتطلب العمليات دور المدير أو صلاحية `employees.manage` الحالية؛ يعيد الخادم 400 للمدخلات أو الأدوار غير الصالحة، و403 لعدم الصلاحية، و404 لموظف خارج العيادة أو غير موجود، و409 للتكرار أو لمحاولة إزالة دور آخر مدير نشط. تحجز معاملة التعديل صف العيادة عبر `SELECT ... FOR UPDATE` وتعيد التحقق من صلاحية المنفّذ وعدد المديرين بعد القفل؛ يجب أن تستخدم عمليات تعطيل المدير القفل نفسه.
