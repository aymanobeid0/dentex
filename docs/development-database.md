# قاعدة التطوير المحلية وتسليم العمل

## الحالة

## التشغيل

- تشغيل قاعدة البيانات: `docker compose up -d --wait`.
- الإيقاف مع الحفاظ على البيانات: `docker compose stop`.
- البيانات محفوظة في volume مستقل. لا تحذف volume لإعادة التشغيل أو التجربة.
- ملف `.env` يحتوي بيانات الاتصال المحلية ومستثنى من Git؛ لا تُطبع محتوياته أو تُنقل إلى المواصفات والتذاكر.
- كلمات مرور الحسابات ليست محفوظة في ملفات المشروع كنص صريح. إعادة تشغيل `node scripts/seed-local.mjs` تتطلب متغيري البيئة `CLINIC_ADMIN_PASSWORD` و`PLATFORM_ADMIN_PASSWORD`، وتتحقق من الحسابات الموجودة دون استبدال كلمات مرورها.

## ما يلزم عند بدء التنفيذ في الشات الجديدة

1. اقرأ AGENTS.md والمواصفة المحلية والتذكرة الأولى وعقد الشاشات، والتزم بالتصميم المعتمد في login-preview.html.
2. الجداول الحالية في database/bootstrap.sql هي أساس تجهيز محلي. قبل استخدام Prisma، أنشئ مخططه المتوافق واعتمد baseline للترحيلات دون إسقاط البيانات. لا تستخدم reset على هذه القاعدة.
3. تنسيق تجزئة كلمات المرور: `scrypt$N$r$p$saltHex$keyHex`، حيث N=32768 وr=8 وp=1 وطول المفتاح 64 بايت. ملح scrypt المستخدم هو النص السداسي نفسه (UTF-8)، وليس تحويله إلى بايتات؛ طابقه عند التحقق. استعمل مقارنة ثابتة الزمن.
4. مدير البرنامج في جدول مستقل. مدير العيادة مربوط بدور admin. تنشأ أيضًا أدوار dentist وreceptionist؛ قائمة الصلاحيات وربطها لم تُجهّز بعد ويجب استكمالها وفق المواصفة. دور admin كامل الصلاحيات داخل عيادته فقط.
5. تجهيز قاعدة البيانات لا ينفذ بعد JWT أو حماية HTTP أو عزل الاستعلامات في التطبيق أو حماية آخر مدير. هذه ضمن تذاكر التنفيذ، مع اختبارات التزامن والعزل.
6. المستخدم يريد بدء تنفيذ التطبيق في شات جديدة. العمل الحالي اقتصر على قاعدة التطوير والحسابات؛ لا تنفذ تذاكر إضافية دون توجيه الشات الجديدة.
